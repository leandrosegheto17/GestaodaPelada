# SPK-0001 — Spike S-01: transação interativa `pg` sobre o Hyperdrive

Reserva: Concluída
Agente: coordenador · Lote: L29 · Dep: TP-0014, TP-0133 · Time-box: 1 d
Pergunta: uma transação interativa com `pg` sobre o Hyperdrive faz commit, desfaz tudo no erro e libera a conexão para a próxima requisição? (SDD §6 S-01, T-15; ADR-014 §3)

## Plano
Decisão do usuário (2026-10-17): sem branch `teste`, a prova roda **direto no branch `production`** (ainda sem dados), com uma tabela descartável `spike_s01` criada pelo dono e removida ao final. Worker de prova (`wrangler dev --remote`, sem deploy) usa o `criarDb`/`emTransacao` do TP-0014 e o Hyperdrive `pelada-prod` (cache desligado).
Casos: (1) commit visível para outra conexão; (2) erro no meio não deixa resto; (3) 50 transações em série e 20 em paralelo sem esgotar a conexão (limite do origin = 20).
Código: `evidencia/s-01/` (`worker.ts`, `wrangler.jsonc`, `rodar.mjs`, `preparar.sql`, `limpar.sql`).
Critério de saída: 3 casos passam → nota em `## Resolução`. Falha → BK com a saída do SDD (driver serverless do Neon só nos casos transacionais, dentro de `infraestrutura/db/`).

## Andamento
- 2026-10-17: código de prova escrito; falta o usuário criar a tabela, rodar o Worker (precisa do token da Cloudflare) e devolver a saída.

## Resolução
**Resultado (2026-10-19): S-01 PASSOU.** Transação interativa com `pg` sobre o Hyperdrive `pelada-prod` (cache desligado), via `wrangler dev --remote`, branch `production`, usando `criarDb`/`emTransacao` do TP-0014.
- Caso 1: commit visível para outra conexão (1 linha).
- Caso 2: erro no meio desfaz tudo (0 linhas) e o erro original sobe (`falha-de-proposito`).
- Caso 3a: 50 transações em série, 0 falhas, 50 linhas.
- Caso 3b: 20 transações em paralelo (limite do origin = 20), 0 falhas, 20 linhas.

**Decisão:** o driver `pg` sobre o Hyperdrive atende; o fallback do SDD (driver serverless do Neon nos casos transacionais) **não é necessário**. Nenhuma tarefa afetada precisa de ajuste de plano.

**Pendente (usuário):** rodar `evidencia/s-01/limpar.sql` no Neon (branch `production`, como dono) para remover `spike_s01`.
