## 1. Plano de execução
**Reaproveitamento:** USAR de `backend/contrato/src` (TP-0005): schema de erro (forma de `.md/mockup/respostas/erro-*.json`), tipo e-mail e limites de `limites.ts` (e-mail ≤ 254, corpo ≤ 16 KB). Não redefinir nenhum desses na API. Repositório sem código de aplicação além do TP-0001/TP-0005.
**Camada:** `src/entrada/worker.ts`, `src/entrada/app.ts` (montagem), `src/entrada/middlewares/{cache,csrf}.ts`, `src/entrada/erros.ts` (respostas 404/422/500) → camada `entrada`; `src/config/index.ts` → `config`; `src/infraestrutura/relogio/index.ts` → `infraestrutura`; `wrangler.jsonc` na raiz (item de topo permitido, SDD §2).
**Referência visual:** não se aplica.

1. `src/infraestrutura/relogio`: `criarRelogio(agora = () => new Date())` com `hoje(): 'AAAA-MM-DD'` e `mes(): 'AAAA-MM'` via `Intl.DateTimeFormat('en-CA', { timeZone: 'America/Sao_Paulo' })`. Único lugar com `new Date()` sem argumento (G-06).
2. `src/config`: `lerConfig(env)` puro, chamado por requisição (sem estado global, ADR-014 §1): URL_PUBLICA obrigatória (`new URL`, https — http só para `localhost`, sem barra final), ENDERECO_NOVO opcional (mesma regra), DONO_EMAIL pelo schema de e-mail do contrato. Inválida → erro 500 genérico e mensagem só no log (sem o valor).
3. `src/entrada/app.ts`: `criarApp({ relogio? })` devolve o Hono; injeta relógio e config em `c.var` (é o ponto de injeção que o TP-0017 usa para o relógio fixo). `worker.ts` só `export default criarApp()` (fábrica, não estado entre requisições).
4. Middlewares em `/api/*`: `Cache-Control: no-store`; CSRF: POST/PUT/PATCH/DELETE sem `X-Pelada: 1` exato → 403 no formato de erro (ADR-003, G-09). `app.notFound` → 404 `nao_encontrado`; `app.onError` → 500 `erro_interno` sem stack/mensagem; helper `responderValidacao(c, erroZod)` → 422 `validacao` com `campos` (usado por todas as rotas futuras).
5. `GET /api/saude` → 200, corpo mínimo sem dado de configuração (não toca banco nesta tarefa).
6. `wrangler.jsonc`: `name: pelada`, `main: backend/api/src/entrada/worker.ts`, `compatibility_flags: ["nodejs_compat"]`, `assets: { directory: "frontend/web/dist", not_found_handling: "single-page-application", run_worker_first: ["/api/*"] }`, `hyperdrive: [{ binding: "HYPERDRIVE", id: <placeholder>, localConnectionString }]` (ids reais vêm do TP-0133), `vars` (URL_PUBLICA, DONO_EMAIL; ENDERECO_NOVO ausente), `env.teste` com `name: pelada-teste`. Sem `placement` smart, sem `limits`.
7. Se `wrangler` não estiver nas devDependencies do TP-0001, adicioná-lo (Seção 1.3) e registrar a mudança de lockfile em `## 4`.

PENDENTE: o limite de corpo de 16 KB (Seção 1.4, L-16) não tem tarefa dona; aplicar aqui com `bodyLimit` em `/api/*` (413) ou deixar para outra tarefa?

## 3. Plano de validação de segurança
- G-09/ADR-003: CSRF por `X-Pelada: 1` em toda escrita `/api/*`, antes de qualquer rota; conferir que não há rota registrada antes do middleware.
- 500 sem detalhe (sem stack, SQL, valor de config) — conferir corpo e que o log não imprime env inteiro (G-08: nada de segredo/token em log).
- `Cache-Control: no-store` em todo `/api/*`, inclusive 404/500.
- G-13: lista fechada de recursos no `wrangler.jsonc`, teste falha fechado; nenhum recurso pago.
- G-18/ADR-010: nenhuma URL absoluta no código; `localConnectionString`/placeholder não é segredo (Postgres local); nenhuma string do Neon versionada (G-21).
- G-06: `new Date()` sem argumento só em `infraestrutura/relogio`.
