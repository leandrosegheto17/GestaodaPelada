1. Arquivo com carimbo real do momento da implementação (o TP-0026 precisa vir depois). `CREATE EXTENSION IF NOT EXISTS pgcrypto;` (também dá `gen_random_uuid()`).
2. `contas`: `id uuid PK default gen_random_uuid()`, `email text NOT NULL` com `CHECK (email = lower(btrim(email)) AND char_length(email) <= 254)` e índice único, `nome text` 2 a 60 (Seção 1.4), `senha_hash text NOT NULL`, `senha_temporaria boolean NOT NULL DEFAULT false`, `e_dono boolean NOT NULL DEFAULT false`, `aviso_privacidade_visto_em timestamptz NULL`, `criada_em timestamptz NOT NULL`. Índice único parcial `contas_um_dono ON contas ((true)) WHERE e_dono`; `CONSTRAINT contas_dono_email CHECK (NOT e_dono OR email = '…')`.
3. `sessoes`: `id uuid PK`, `token_hash bytea NOT NULL UNIQUE` (32 bytes, `CHECK (octet_length = 32)`), `conta_id` FK contas, `escopo text CHECK IN ('completo','troca_de_senha')` (enum do `contrato/base`), `criada_em`, `ultimo_uso_em`, `expira_em` (timestamptz NOT NULL); índice por `conta_id`.
4. `tentativas_login`: `id bigint identity`, `email text NOT NULL`, `momento timestamptz NOT NULL`, `sucesso boolean NOT NULL`; índice `(email, momento)`.
5. `pedidos_reset`: `id uuid PK`, `conta_id` FK, `ultimo_pedido_em timestamptz NOT NULL`, `resolvido_em timestamptz NULL`, `resolvido_por uuid NULL` FK contas; índice único parcial `(conta_id) WHERE resolvido_em IS NULL`.
6. `auditoria`: `id bigint identity`, `autor_conta_id uuid NULL` FK contas, `autor_tipo text CHECK IN ('conta','infraestrutura')` + `CHECK ((autor_tipo = 'conta') = (autor_conta_id IS NOT NULL))`, `acao text`, `entidade text`, `entidade_id text NULL`, `grupo_id uuid NULL` (sem FK: a tabela de grupos nasce no TP-0026), `momento timestamptz NOT NULL`, `resumo jsonb NOT NULL DEFAULT '{}'`; índice `(grupo_id, momento)`.
7. Momentos sem `DEFAULT now()`: vêm do relógio da API (G-06; testes com relógio fixo nos repositórios). Tipos enumerados como `text` + `CHECK` (acrescentar valor é aditivo).
8. Acrescentar as 5 tabelas em `TabelasBanco` (`tipos.ts`) aqui, para os repositórios paralelos (TP-0027, TP-0028, TP-0030) não editarem o mesmo arquivo.

## 3. Plano de validação de segurança
- ADR-013/G-11: unicidade do dono garantida no banco (índice parcial + CHECK); nada além da migração escreve `e_dono` nesta tarefa.
- ADR-003/ADR-015: só o hash do token (`bytea` de 32 bytes) e só `senha_hash` (nenhuma coluna de senha em claro ou token).
- LGPD (SDD §7): `tentativas_login` e `auditoria` sem IP, user-agent ou telefone; `resumo` da auditoria nunca recebe senha/token (regra dos repositórios, documentada no comentário da coluna).
- G-14/G-07: migração aditiva, sem tipo de ponto flutuante; nenhum segredo no SQL (G-21) — o e-mail do RF-01 é público no PRD.
