# TP-0007 — `dominio/datas`: mês, navegação de mês e dias de jogo sugeridos

Reserva: Livre
ID no TASK.md: TP-0007 · Lote: L02 · Agente: executor · Chapéu: Backend · Est: 0,5 d · Dep: TP-0001 · Status no TASK.md: Pendente
Reqs: RN-07, I-26, RF-25, RF-39; ADR-012 · Aceite: [PD] Mês de uma data, 1º e último dia, mês anterior e seguinte, comparação, dia da semana; data sugerida da partida (dia da semana do grupo mais recente ≤ hoje) e próximo dia de jogo (≥ hoje), recebendo `hoje`. Quinzenal e mensal usam o dia da semana (L-6). Testes: virada de mês e de ano, 29/02, hoje = dia de jogo

## 1. Plano de execução
**Reaproveitamento:** usa só o pacote `backend/dominio` criado por TP-0001 (package.json, tsconfig, Vitest). Nada de código de domínio existe ainda; este módulo é a base que TP-0008, TP-0009, TP-0010, TP-0148 e TP-0187 vão usar — tudo o que for aritmética de data fica aqui, nunca reimplementado nos outros módulos.
**Camada:** `@pelada/dominio` (`backend/dominio/src/datas/`), regra pura (SDD §2 "Pacotes, pastas e fronteiras").
**Referência visual:** não se aplica.

1. Tipos: `Data` = string `AAAA-MM-DD`, `Mes` = string `AAAA-MM` (ADR-012 §1). Dia da semana como índice `0..6` (0 = domingo), para o domínio não depender da grafia do enum do contrato (o adaptador da `aplicacao/` converte; G-01 proíbe importar `@pelada/contrato`).
2. `backend/dominio/src/datas/datas.ts` (funções pequenas, exportadas): `mesDe(data)`, `primeiroDia(mes)`, `ultimoDia(mes)` (28/29/30/31 com bissexto), `mesAnterior(mes)`, `mesSeguinte(mes)`, `compararDatas(a,b)`/`compararMeses(a,b)` (comparação lexicográfica é válida no formato fixo), `somarDias(data, n)` (será usado pela véspera do RN-08 e por atividade), `diaDaSemana(data)`.
3. `backend/dominio/src/datas/dia-de-jogo.ts`: `dataSugeridaPartida(hoje, diaSemana)` = maior data ≤ `hoje` com aquele dia da semana (RF-25); `proximoDiaDeJogo(hoje, diaSemana)` = menor data ≥ `hoje` (RF-39, "hoje incluso"). A frequência não entra no cálculo (L-6): a assinatura não recebe frequência.
4. Implementação de calendário com `Date.UTC(a, m-1, d)` + `getUTCDay()`/`getUTCDate()` (sempre com argumento; G-06 proíbe `new Date()`/`Date.now()` sem argumento no domínio). Nunca usar `getDay()` local nem `toISOString` de instante com fuso.
5. Exportar o módulo pelo ponto de entrada do pacote definido em TP-0001 (`backend/dominio/src/index.ts` ou subcaminho em `exports`): reler antes de editar, só acrescentar a linha (TP-0011/TP-0012 editam o mesmo arquivo em paralelo).
6. Ordem TDD: tabela de casos (seção 2) primeiro, depois implementação.

Não fazer: ler relógio, aceitar `Date` como entrada, validar formato com regex do contrato (a entrada chega validada pelo `contrato/base`), lógica de frequência quinzenal/mensal.

## 2. Plano de teste
Vitest em `backend/dominio/src/datas/datas.test.ts` e `dia-de-jogo.test.ts`, testes de tabela ([PD]):
- `mesDe('2026-10-22')='2026-10'`; `primeiroDia/ultimoDia`: 2026-02 → 28, 2028-02 → 29, 2100-02 → 28, 2000-02 → 29, 2026-12 → 31, 2026-04 → 30.
- Virada: `mesAnterior('2026-01')='2025-12'`, `mesSeguinte('2026-12')='2027-01'`; `somarDias('2028-02-28',1)='2028-02-29'`, `somarDias('2026-12-31',1)='2027-01-01'`, `somarDias('2026-03-01',-1)='2026-02-28'`.
- `diaDaSemana('2026-10-22')=4` (quinta), `'2028-02-29'=2`.
- Sugerida/próximo com hoje = dia de jogo (`2026-10-22`, quinta → ambos `2026-10-22`); hoje sexta 2026-10-23 → sugerida 22/10, próximo 29/10; virada de mês (hoje 2026-11-02, domingo → sugerida 2026-11-01; quinta → sugerida 2026-10-29) e de ano (hoje 2027-01-01 sexta, quinta → 2026-12-31); 29/02 como resultado.
- Comando: `pnpm --filter @pelada/dominio exec vitest run src/datas`; antes de devolver, `pnpm lint`, `pnpm typecheck` e `node backend/scripts/checagens/checar-ids-tarefa.mjs` (Seção 1.6, se já existirem).
