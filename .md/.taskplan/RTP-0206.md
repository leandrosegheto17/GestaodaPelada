# RTP-0206 — `pnpm snapshot` do contrato grava JSON sem formatar numa pasta que o `format:check` confere (achado da revisão 2026-10-22 (3))

Reserva: Livre
ID no TASK.md: RTP-0206 · Lote: Refatoração Revisão 2026-10-22 · Agente: executor · Chapéu: Backend · Est: 0,2 d · Dep: - · Status no TASK.md: Pendente
Reqs: - · Aceite: depois de `pnpm --filter @pelada/contrato snapshot` seguido de `pnpm format:check` na raiz, o `format:check` passa sem rodar mais nenhum comando (a gravação já deixa `backend/contrato/snapshot/*.json` no formato do prettier, ou o script `snapshot` encadeia a formatação); `pnpm --filter @pelada/contrato snapshot` duas vezes seguidas não deixa nenhum arquivo modificado no `git status`; `snapshot-lib.test.ts` ou teste novo em `ferramentas/` cobre a saída formatada (ex.: array curto `required` em uma linha). Origem: revisão 2026-10-22 (3), item 17 — `serializar` em `snapshot-lib.ts:41` usa `JSON.stringify(..., null, 2)` (arrays sempre expandidos), mas os arquivos versionados estão no estilo prettier (ex.: `"required": ["codigo", "mensagem"]` em `snapshot/erro.json:27`) e o CI roda `format:check` (`ci.yml:32`); quem regera o snapshot recebe dezenas de arquivos modificados só de formato (o `git status` de hoje mostra ~45 arquivos em `backend/contrato/snapshot` modificados) e esconde a mudança real de contrato.

## 1. Plano de execução
Preferir a opção mais simples: no `package.json` de `backend/contrato`, `"snapshot": "tsx ferramentas/snapshot.ts && prettier --write snapshot"` (prettier já é dependência da raiz; conferir que o binário resolve a partir do pacote, senão usar `pnpm -w exec prettier`). Alternativa só se a primeira não resolver: `gravar` chamar a API do prettier. `desatualizados` em `conferir` compara pelo conteúdo serializado dos dois lados e não depende do formato; não mexer.
**Reaproveitamento:** reusar a configuração de prettier da raiz e o script `snapshot` existente; nenhuma ferramenta nova. Registrar em `backend/contrato/ferramentas/snapshot.ts` (mensagem de saída) que a pasta fica formatada.

## 2. Plano de teste
Rodar o script duas vezes e conferir `git status` de `backend/contrato/snapshot` sem diferença extra entre a 1ª e a 2ª; `pnpm format:check`; `pnpm --filter @pelada/contrato test` e `checar-compatibilidade` verdes.

## 3. Plano de validação de segurança
Só ferramenta de desenvolvimento; confirmar que `checar-compatibilidade` continua falhando quando um campo é removido (teste existente em `snapshot-lib.test.ts`) e que nenhum arquivo do snapshot perdeu conteúdo (comparar JSON parseado antes e depois).
