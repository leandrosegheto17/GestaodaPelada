# TP-0211 — `dominio/periodos-corrigiveis`: tipo do período e o que se pode corrigir

Reserva: Livre
ID no TASK.md: TP-0211 · Lote: L48 · Agente: executor · Chapéu: Backend · Est: 0,5 d · Dep: TP-0009 · Status no TASK.md: Pendente
Reqs: RF-76, RF-77; RN-30 · Aceite: função pura que, dada a lista de períodos com id, devolve em ordem cronológica `tipo` (entrada no 1º, retorno nos demais) e `corrigivel { saida, retorno }` (1º aberto = nada; 1º encerrado = só saída; aberto que não é o 1º = só retorno; demais = os dois), mais por período a saída anterior e o início do próximo; ids preservados; entrada não é alterada; arquivo ≤ 300 linhas

## 1. Plano de execução
**Reaproveitamento:** tipo `Periodo` e `ComPeriodos` de `backend/dominio/src/atividade/atividade.ts` (estender com `id`: `Periodo & { id: string }`, sem redefinir início/fim); `compararDatas` de `backend/dominio/src/datas/datas.ts` para ordenar. Não repetir a ordenação de `validar-periodos.ts` se ela já virar auxiliar; senão ordenar aqui por `compararDatas(a.inicio, b.inicio)`.
**Camada:** `@pelada/dominio`, `backend/dominio/src/atividade/periodos-corrigiveis.ts` (novo), exportado em `backend/dominio/src/index.ts`. Puro (G-05, G-06).
**Referência visual:** não se aplica.
Passos (TDD):
1. Teste primeiro em `backend/dominio/test/atividade/periodos-corrigiveis.test.ts` (tabela da Seção 2).
2. Tipos: `PeriodoComId = Periodo & { id: string }`; `PeriodoCorrigivel { id; tipo: 'entrada' | 'retorno'; inicio; fim: Data | null; corrigivel: { saida: boolean; retorno: boolean }; saidaAnterior: Data | null; inicioDoProximo: Data | null }`.
3. `descreverPeriodos(periodos: readonly PeriodoComId[]): PeriodoCorrigivel[]`: copia, ordena por início, e para cada índice i: `tipo = i === 0 ? 'entrada' : 'retorno'`; `retorno = i > 0`; `saida = fim !== null` (o 1º aberto: saida false e retorno false; o 1º encerrado: saida true; aberto não-1º: retorno true e saida false; demais: ambos).
4. `saidaAnterior` = `fim` do período i-1 (nulo para i = 0); `inicioDoProximo` = `inicio` do i+1 (nulo para o último).
5. Preservar `id`; não mutar a entrada. Exportar no `index.ts`.
**O que NÃO fazer:** não validar sobreposição (é `validarPeriodos`/`avaliar-periodos`); não montar texto de ajuda (tela e `aplicacao` só consomem o campo, G-05); não decidir ordem pelo `id`; não ler banco nem relógio; sem `TP-`/`Lote` em comentário.

## 2. Plano de teste
- 1 período aberto: `{ saida:false, retorno:false }`, tipo `entrada`; 1 encerrado: `{ saida:true, retorno:false }`.
- 2 períodos (1º encerrado, 2º aberto): 1º só saída; 2º `retorno` e só retorno.
- 3 períodos (os dois do meio completos): 2º com `{ saida:true, retorno:true }`; `saidaAnterior` e `inicioDoProximo` de cada um conferidos.
- Entrada fora de ordem: saída ordenada cronologicamente.
- Saída igual ao retorno seguinte (`[a,d)` e `[d,∞)`): preservada, sem erro.
- Ids preservados no mesmo período após a ordenação; lista vazia devolve `[]`; entrada congelada (`Object.freeze`) não é alterada.
- Comando: `pnpm --filter @pelada/dominio test -- periodos-corrigiveis atividade`.
