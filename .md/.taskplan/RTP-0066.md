# RTP-0066 — Teste anti-enumeração: provar também o custo bcrypt do hash fixo

Reserva: Livre
ID no TASK.md: RTP-0066 · Lote: Refatoração Lote-L06 · Agente: executor · Chapéu: Backend · Est: 0,1 d · Dep: RTP-0060 · Status no TASK.md: Pendente
Reqs: TP-0027; ADR-015 §4; RNF-05 · Aceite: o teste de contas falha se o `HASH_FIXO` de `verificarSenha` tiver custo diferente do hash real (cost 12): ler o custo de ambos (prefixo `$2a$NN$`) e exigir igualdade; mutação `HASH_FIXO` com cost 04 faz o caso falhar

## 1. Plano de execução
Origem: DevSecOps da RTP-0060 (baixa). O caso novo conta 1 chamada de `crypt` nos dois caminhos, mas não prova que o custo é igual: trocar o `$2a$12$` do `HASH_FIXO` por `$2a$04$` mantém o teste verde e reabre a enumeração por tempo (o teste de tempo antigo foi removido).
1. Exportar o custo do hash fixo (ou o próprio hash) do módulo de contas e, no caso "um crypt cada", comparar o custo extraído do `senha_hash` de uma conta criada com o do hash fixo.
2. Mutação: `HASH_FIXO` com cost 04 deve falhar o caso.

## 2. Plano de teste
`npx vitest run test/repositorios/contas.test.ts` (banco próprio); mutação do custo do `HASH_FIXO` falha, fonte restaurada.

- Teste: `DATABASE_URL_TESTE=...:55432/pelada_teste_rtp0066 npx vitest run --project node contas.test` -> 8 passando. Mutação cost 04 -> 1 falha ("expected '04' to be '12'"); fonte restaurada. Banco removido.
