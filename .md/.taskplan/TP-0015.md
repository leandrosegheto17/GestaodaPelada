## 1. Plano de execução
**Reaproveitamento:** nada a reaproveitar (só o `monorepo` do TP-0001). Esta tarefa CRIA a trava de host que `dono.ts` (TP-0041), `seed-local.ts` (TP-0051), `anonimizar-jogador.ts` e o suporte de testes (TP-0014, TP-0017) devem usar — por isso ela nasce fora da CLI.
**Camada:**
- `backend/api/src/infraestrutura/seguranca/trava-host.ts` → `infraestrutura/seguranca` (import permitido a `backend/scripts`, G-01/L-2): função pura, sem `pg`.
- `backend/api/src/infraestrutura/db/migracoes/aplicar.ts` → módulo de dados (único com `pg`, G-02): `aplicarMigracoes(connectionString, migracoes: {nome, sql}[])`.
- `backend/api/src/infraestrutura/db/migracoes/` com `.gitkeep` (as migrações das próximas tarefas entram aqui).
- `backend/scripts/migrar.ts` → ponto de entrada fino: lê argumentos e env, lista e lê os `.sql`, chama trava e `aplicarMigracoes`.
**Referência visual:** não se aplica.

1. Trava: `exigirHostPermitido({ url, alvo, ci, confirmar })`. Host local = `localhost`, `127.0.0.0/8`, `::1` e `db` (serviço do compose, TP-0094), comparados após `toLowerCase()` e sem colchetes. Não local → exige `alvo ∈ {producao, teste}` e (`ci === 'true'` ou `confirmar()` devolver exatamente o host). Recusa: URL ausente ou não parseável, host vazio, vários hosts (`h1,h2`), `host`/`hostaddr` na query string (libpq sobrescreve o host da URL), socket (`/var/run/...`). Mensagem de erro sem a senha da URL.
2. `aplicarMigracoes`: `CREATE TABLE IF NOT EXISTS migracoes_aplicadas (nome text primary key, aplicada_em timestamptz not null default now())`; lê os nomes já aplicados; para cada pendente em ordem: `BEGIN` → SQL → `INSERT` do nome → `COMMIT`; erro → `ROLLBACK`, relança com o nome do arquivo e não segue. Cliente fechado em `finally`.
3. `migrar.ts`: variável `DATABASE_URL` (acrescentar em `backend/.env.example` sem valor — registrar em `## 4`), `--alvo`, `CI`; confirmação via `readline` só se TTY. Nome fora de `^\d{12}_[a-z0-9_]+\.sql$` → falha antes de aplicar qualquer coisa. Ordem = `sort()` por nome. Saída: lista aplicadas/puladas; código 1 em erro.
4. Execução TS no Node 22: usar o mecanismo que o TP-0001 definiu nos `package.json` (script `migrar`); se não houver, PENDENTE de dependência (não instalar `tsx` sem registrar).

Não fazer: checagem aditiva (TP-0016), migração de schema de negócio (TP-0025+), docker-compose (TP-0094).
