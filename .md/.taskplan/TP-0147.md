## 1. Plano de execução
**Reaproveitamento:** nada a reaproveitar (Dep só TP-0001; só o pacote `backend/dominio`). Este módulo passa a ser a única fonte da composição de times: TP-0152 (distribuição vários) e TP-0153 (aviso (d)) devem usar `composicaoVarios` daqui, não refazer a conta.
**Camada:** `@pelada/dominio`, `backend/dominio/src/simulador/previa.ts` (SDD §2, árvore `src/simulador`). Regra pura, inteiros (ADR-007 §4-5).
**Referência visual:** não se aplica (formas de saída em `.md/mockup/respostas/simulador-previa-*.json`).

1. Tipos próprios do domínio (G-01 proíbe importar o enum do contrato): `Formato = 'dois_times' | 'varios_times'`; entrada `{ formato, n, aptos: number }` (quantidade; N e aptos já validados pelo contrato).
2. `composicaoVarios(aptos, n)` → `{ times: ceil(aptos/n), timesCompletos: floor(aptos/n), tamanhoTime: n, tamanhoIncompleto: aptos % n }` (0 = sem incompleto); só inteiros (`Math.floor`/divisão inteira, sem float).
3. `calcularPrevia(entrada)` → união discriminada:
   - dois, aptos ≥ 2N: `{ valida: true, times: 2, reservas: aptos − 2N }`;
   - dois, aptos < 2N: `{ valida: false, motivo: 'aptos_insuficientes', maiorNPossivel: floor(aptos/2) }`, `null` quando < 2 (N mínimo de RF-39);
   - vários, aptos > 2N: `{ valida: true, ...composicaoVarios }` (T ≥ 3, I-38);
   - vários, aptos ≤ 2N: `{ valida: false, motivo: 'aptos_insuficientes', nSugerido }` com `nSugerido` = maior N ≥ 2 com aptos > 2N, isto é `floor((aptos − 1)/2)`, ou `null` quando < 2; e `doisTimesPossivel = aptos ≥ 4`.
4. Texto ("4 times de 4 + 1 time incompleto de 2", "Faltam aptos para 2 times de 11. Maior N possível: 9.") não é do domínio: o adaptador da rota (TP-0163) monta `descricao` a partir desta saída.
5. Export pelo ponto de entrada do pacote (reler antes; TP-0148/TP-0149 editam em paralelo; só a linha nova). TDD: tabela de casos primeiro.
