## 1. Plano de execução
Origem: QA da RTP-0061 (média). Sondas executadas pelo QA, todas exit 0 sem `grupoId`:
(a) `export class C { constructor(id: string) { fetch(id); } }`, `export class C extends Error { constructor(id: string) { super(id); fetch(id); } }`, `constructor(@d id: string)`;
(b) `partidas.ts: export * from "./x.test"` / `export { f } from "./x.test"` / `export * as n from ...` / `import * as n from "./x.test"; export { n }` e o mesmo com `x.mts`/`x.tsx` (listar só considera `.ts` sem `.test.ts`; o dono fora de `arquivos` nunca é avaliado);
(c) `export const f = null as unknown as (id: string) => Promise<void>`, `[] as unknown as Array<(id: string)=>void>`, `{} as unknown as { q(id: string): Promise<void> }`, `export class C { f = "x" as unknown as (id: string)=>void }`, `constructor(public f = null as unknown as (...)=>void)`, `{ a: "s" as unknown as (...)=>void }`, index signature com tipo função;
(d) `function f(id: string){}; export = f;` e `export = obj` (exit 0; tsc em ESM já recusa, mas o guarda não deveria depender disso).
1. Construtor: aceitar só parâmetros-propriedade de dado e corpo vazio ou só `super(...)` de argumentos identificadores/literais; demais, não analisável.
2. Incluir no conjunto avaliado todo arquivo da pasta resolvido por export (qualquer extensão TS e `.test.ts`), ou falhar quando o dono estiver na pasta mas fora de `arquivos`.
3. Casts: se houver `as`/`satisfies` cujo tipo contenha função/método/tipo não dado, não analisável (checar o tipo do nó, não só o inicializador).
4. `ExportAssignment` com `isExportEquals`: não analisável.
5. Um teste "falha" por sonda.

## 3. Plano de validação de segurança
As sondas acima saem com código ≠ 0; dados literais, `extends Error` e classes só com parâmetros-propriedade de dado continuam passando.

Padrão repetido: 4ª rodada do guarda G-03 (RTP-0019, 0057, 0061, 0064) a fechar contornos por forma sintática. Regra sugerida: o guarda deve decidir pelo tipo/valor de cada export via verificador de tipos (todo símbolo cujo tipo tenha assinatura de chamada ou construtor exige grupoId ou exceção) e pelo conjunto de arquivos do programa, não por enumeração de nós; a RTP-0064 deve adotar esse critério, não somar mais casos.

## 4. Resultado da execução
Critério adotado (não mais enumeração de sintaxe): além da lista de permitidos sintática, todo export que não é função passa pelo verificador de tipos. `tipoInvocavel` recusa tipo com assinatura de chamada/construção (em profundidade: propriedades, índices, argumentos de tipo, união/interseção) e any/unknown/object; vale para const, `export default`, instância e lado estático da classe (só membros próprios; membros herdados da lib, ex. `Error.cause`, ignorados). Cobre todos os casts (c) pelo tipo resultante.
- Construtor (a): parâmetros identificadores, sem decorador, padrão literal; corpo vazio ou só `super(identificadores/literais)`. Decoradores de classe/membro e nomes computados recusados.
- Arquivos (b): `listar` agora considera ts/tsx/mts/cts (exceto `.test.*`); dono dentro da pasta mas fora do conjunto avaliado (ex. `.test.ts`), por `export from`, alias ou `import * as`, gera achado.
- (d): `export =` gera achado (exceção chave `export=`); `funcaoDe`/`declaracaoEhDado` ignoram `isExportEquals`.
- Também removido `ehCallable` (não usado, lint).
