# RTP-0210 — Fixar fim de linha LF no repositório (`.gitattributes`), já que o prettier aceita CRLF com `endOfLine: auto`

Reserva: Livre
ID no TASK.md: RTP-0210 · Lote: Refatoração Revisão 2026-10-22 · Agente: executor · Chapéu: Backend · Est: 0,2 d · Dep: RTP-0208 · Status no TASK.md: Pendente
Reqs: - · Aceite: `.gitattributes` na raiz com `* text=auto eol=lf`; `git ls-files --eol` continua `i/lf` para todos os arquivos de texto; `pnpm format:check` passa depois de `git add --renormalize .` sem alterar conteúdo. Origem: QA da RTP-0208 — com `endOfLine: auto`, um arquivo CRLF commitado passaria no CI.

## 1. Plano de execução
Criar `.gitattributes` na raiz com `* text=auto eol=lf` (arquivos binários já cobertos pelo `text=auto`). Conferir `git ls-files --eol` antes e depois e que nenhum arquivo versionado muda de conteúdo (`git add --renormalize .` não deve produzir diff de conteúdo). Cuidado: não renormalizar nem commitar arquivos pendentes de outras tarefas.
**Reaproveitamento:** nenhum arquivo novo além do `.gitattributes`; a regra de fim de linha do prettier (`auto`) permanece.

## 2. Plano de teste
`git ls-files --eol | grep -v 'i/lf'` vazio para texto; `pnpm format:check` verde; `pnpm --filter @pelada/contrato test` verde.

## 3. Plano de validação de segurança
Sem mudança de comportamento; confirmar que o `.gitattributes` não altera arquivos binários (imagens, fontes) nem scripts que dependam de CRLF.
