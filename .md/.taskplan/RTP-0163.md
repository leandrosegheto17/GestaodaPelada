# RTP-0163 — Alinhar docs ao deploy só manual

Reserva: Livre
Origem: QA da TP-0139 (F3, não crítico). O `deploy.yml` virou `workflow_dispatch` sem aprovação (commit 3b13d475; G-15 e backend/DEPLOY.md já ajustados), mas ainda dizem "push na main"/"aprovação manual": `.md/SDD.md` §3 (linha do `deploy.yml`), `.md/adr/020-...md` linha 27, `backend/README.md` linha 72, comentário de `backend/scripts/checagens/checar-wrangler-deploy.mjs` ("aprovação do environment producao"). O aceite da TP-0135 no TASK.md também diz "sem workflow_dispatch", histórico: não reescrever, só registrar a decisão no ADR-020.

## 1. Plano de execução
Editar só texto nos 4 arquivos acima para refletir: disparo manual (`gh workflow run deploy.yml --ref main`), environment `producao` sem revisor obrigatório, decisão do Leandro de 2026-10-19. Nenhum código de lógica.

## 2. Plano de teste
`grep -n "aprovação manual\|push na main\|push em" ` nos 4 arquivos sem o texto antigo; `pnpm exec vitest run backend/scripts/checagens` verde.

## 4. Resultado da execução
Feito: texto alinhado ao deploy só manual (`workflow_dispatch`, `gh workflow run deploy.yml --ref main`, environment `producao` sem revisor, decisão de 2026-10-19).
Arquivos (5): `.md/SDD.md` (linha do `deploy.yml` na §3 e a linha 302 da árvore, "main e teste" -> "disparo manual"), `.md/adr/020-host-prod-ljs-workers-dev-sem-homologacao.md` (linha 27 + item de atualização registrando que a barreira passa a ser o disparo manual + branch policy do environment, com a perda da aprovação explícita dita), `backend/README.md` (linha 72), comentário de `backend/scripts/checagens/checar-wrangler-deploy.mjs`.
Já sujos antes (outra tarefa, Edit mínimo, nada revertido): `.md/SDD.md` e `.md/TASK.md` (TP-0208); `.md/TASK.md` não foi tocado por mim.
Testes: `grep -n "aprovação manual|push na main|push em"` nos 4 arquivos: sem ocorrências (grep=1). `pnpm exec vitest run backend/scripts/checagens`: 304 passando, 11 skipped, 4 falhando, todos alheios à mudança (seed-local.test.ts: ECONNREFUSED na porta 55432, banco local desligado; banco.test.mjs checar-grupo-id: 2 timeouts de 5s sob carga, em teste que não toca o arquivo editado). Nenhum teste cobre o `.mjs` editado além do comentário.
Checklist de convenções: só texto/comentário; sem ID de tarefa em código; sem arquivo > 300 linhas criado. Lint/typecheck globais não rodados (só comentário alterado).
Risco: o ADR registra que a segunda pessoa/aprovação por deploy deixou de existir; a branch policy do environment precisa estar de fato configurada no GitHub (não verificável daqui).

## 3. Plano de validação de segurança
Conferir que o texto não esconde a perda do controle de aprovação: registrar no ADR-020 que a barreira passa a ser o disparo manual + branch policy do environment.

## 5. Resultado do QA
Veredito: APROVADA.
- Grep `aprovação manual|push na main|push em|push na` nos 4 arquivos (+ backend/DEPLOY.md): só restam as 2 ocorrências "o push na `main` não dispara deploy" (ADR-020 l.28, README l.72), que são a negação correta, não o texto antigo.
- Fidelidade: deploy.yml tem `on: workflow_dispatch` e `environment: producao`; DEPLOY.md l.8 diz o mesmo (`gh workflow run deploy.yml --ref main`). SDD §3 (linha do deploy.yml e árvore l.302, conferidos via `git diff .md/SDD.md`) e README l.72 batem.
- ADR-020: registra que o environment não exige mais revisor e que a barreira passa a ser disparo manual + branch policy (só main), com a perda da aprovação explícita dita. Atende o plano de segurança.
- Testes: `vitest run backend/scripts/checagens` = 306 passando, 11 skipped, 2 falhas de teste + seed-local (ECONNREFUSED 55432, banco local desligado). As 2 de banco.test.mjs (checar-grupo-id, timeout 5s) falham também rodando o arquivo isolado (sem carga). Esse teste não referencia checar-wrangler-deploy.mjs, e a mudança nesse .mjs é só comentário: preexistentes, alheias à tarefa.
- Convenções: comentário editado descreve o porquê, sem ID de tarefa; sem lógica alterada. Observação: a linha do comentário passa de ~120 colunas (sem regra de limite violada que cause achado).
- Fora do verificável: a branch policy do environment no GitHub (risco já declarado no ## 4).
Achados: 0 críticos, 0 não críticos. RTPs: nenhuma.
Resumo para o relatório: APROVADA; 0 achados; docs fiéis ao deploy.yml (workflow_dispatch, environment producao) e ao DEPLOY.md, ADR-020 com a barreira; falhas de seed-local (banco desligado) e banco.test.mjs (timeouts, também isolado) preexistentes.

## 6. Resultado do DevSecOps
Veredito: APROVADA (revisão do diff do commit c3743eaf + trecho do deploy em `git diff .md/SDD.md`; não é auditoria de release).

LIDO:
- ADR-020 l.27-28: diz que o environment `producao` não exige mais revisor, que o push na `main` não dispara deploy, que a barreira passa a ser disparo manual + branch policy (só `main`) + branch de restauração + dump cifrado, e que "perde-se a segunda pessoa/aprovação explícita". A perda do controle não fica escondida.
- G-15 (GUARDRAILS.md l.28): `workflow_dispatch`, sem aprovação, decisão do Leandro 2026-10-19; coerente com SDD §3, README l.72, DEPLOY.md e o comentário do `.mjs` (nenhum afirma aprovação manual).
- Comentário do `.mjs`: "o controle real é a revisão de PR e o disparo manual restrito à main (branch policy)". Só texto, sem lógica alterada.

EXECUTADO:
- `gh api repos/{owner}/{repo}/environments/producao`: protection_rules = apenas `branch_policy` (sem `required_reviewers`), `custom_branch_policies: true`; `deployment-branch-policies` lista só `main`. A branch policy afirmada nos textos está confirmada hoje no GitHub, e a ausência de revisor também bate com o texto.
