## 1. Plano de execução

Comum com TP-0079 (paralelo) e TP-0168: `montarLinhas(jogadores, presencas?)` → `LinhaPresenca[]` (`ausente` sem presença) em `src/aplicacao/partidas/linhas.ts` — ler antes; quem chegar primeiro cria. O 409 de duplicada também é do POST (TP-0081): criar `responderPartidaDuplicada(c, data)` em `src/entrada/erros.ts` (mensagem "Já existe uma partida em dd/mm/aaaa." + `dataExistente`), para os dois usarem.
**Camada:** `src/aplicacao/partidas/{nova.ts,linhas.ts}` → `aplicacao`; `src/entrada/rotas/grupos/partidas/nova.ts` → `entrada`; `src/entrada/erros.ts` (só a função nova); uma linha em `src/entrada/app.ts` (reler antes).
**Referência visual:** não se aplica.

1. TDD (Seção 2) primeiro.
2. Rota `GET /api/grupos/:grupoId/partidas/nova`: `hoje` do relógio; `data` da query; inválida (`2026-02-30`, `abc`) ou futura → 422 `validacao` com `campos.data` (forma de `erro-data-futura.json`).
3. `prepararPartidaNova(db, grupoId, { data?, hoje })`: `buscarPorId` → `dataSugerida = dataSugeridaPartida(hoje, indiceDiaSemana(grupo.diaSemana))`; `data ?? dataSugerida`; `porData(data)` não nulo → `PartidaDuplicada(data)` → 409; senão `ativosNaData` → `montarLinhas` (todos `ausente`, RF-25). Resposta `{ data, dataSugerida, hoje, jaExiste: false, preMarcadaPelaEscalacao: false, choveu: false, jogadores }`, validada por `PartidaNova`.
4. Rota registrada em caminho estático `partidas/nova`; o TP-0079 usa parâmetro com padrão de data, então não há colisão de rota.
5. `casos.ts`: `GET /api/grupos/:grupoId/partidas/nova` → `tipo: 'grupo'` (`parametros`: `data` = hoje do relógio fixo).
6. Não fazer: pré-marcação pela escalação (TP-0168); decidir ativos fora de `ativosNaData`.

## 2. Plano de teste
`backend/api/test/aplicacao/partidas/{nova,linhas}.test.ts` e `backend/api/test/rotas/grupos/partida-nova.test.ts` (pool de Workers + Postgres; fábricas apagadas no `afterEach`; relógio fixo, datas derivadas, sem literal — §7):
- [PR] sem `?data` com hoje = dia de jogo → `data = dataSugerida = hoje`; hoje um dia depois → sugerida = véspera; passa em `PartidaNova` (chaves de `partida-nova-2026-10-22.json`).
- ativos: entrada depois da data fica fora, saída na data fica fora (semiaberto), ordem alfabética com acento ("Álvaro" < "beto"); todos `ausente`; jogador de outro grupo nunca aparece.
- data sem ativos → `jogadores: []` (forma de `partida-nova-sem-ativos.json`).
- amanhã → 422 `campos.data` = "A data não pode ser no futuro."; `2026-02-30`/`abc` → 422.
- data já lançada → 409, corpo de `erro-partida-duplicada.json` com `dataExistente` e a data formatada; partida do grupo B na mesma data não bloqueia A.
- outro grupo/uuid malformado → 404; sem sessão → 401; `no-store`; isolamento verde.
Comando: `pnpm --filter @pelada/api test -- partida-nova nova linhas isolamento` (+ `pnpm --filter @pelada/contrato test -- partidas` se extrair `dataAteHoje`) + Seção 1.6.
