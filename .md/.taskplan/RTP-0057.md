# RTP-0057 — checar-grupo-id: cobrir alias, ternário, acesso a membro, namespace e arrow com satisfies

Reqs: RTP-0019; G-03; SDD §6 · Aceite: `checar-grupo-id.mjs` sai ≠ 0 para export sem `grupoId` nas formas: alias de função (`export const f = a`), ternário/`||` de funções, acesso a membro (`o.l`), `await` de função, função dentro de `export namespace` e arrow com `satisfies`/`as` (`((id) => id) satisfies unknown`); teste para cada caso.

## 1. Plano de execução
Origem: DevSecOps da RTP-0019 (média). Sondas executadas, todas com exit 0: `const a = (id: string) => id; export const f = a;`, `export const f = true ? a : b;`, `export const f = o.l;`, `export const f = a || a;`, `export namespace N { export function g(id: string) {...} }`, `export const f = await Promise.resolve((id: string) => id);`, `export const f = ((id: string) => id) satisfies unknown;`. `formaNaoAnalisavel` só cobre chamada/new/class/objeto; `funcaoDe` não desembrulha `satisfies`/`as` no inicializador. O guarda G-03 segue contornável.
1. Em `formaNaoAnalisavel`: após `exprSemAsserts`, falhar fechado para qualquer inicializador que não seja arrow/function expression nem literal de dado (identificador, acesso a membro, condicional, binária, await etc.); em `funcaoDe`, usar `exprSemAsserts` para arrow/function com `satisfies`/`as`.
2. Tratar `ModuleDeclaration` (namespace) como forma não analisável ou descer nos membros.
3. Testes em `test/banco.test.mjs` para cada sonda.
