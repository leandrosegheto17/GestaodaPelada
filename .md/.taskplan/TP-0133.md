## 1. Plano de execução
**Reaproveitamento:** USAR o `wrangler.jsonc` da raiz criado pelo TP-0013 (binding `HYPERDRIVE` com id placeholder na raiz e `env.teste` com `name: pelada-teste`) e o `wrangler` das devDependencies (`pnpm exec wrangler`). USAR as strings diretas do `pelada_app` de `main` e `teste` guardadas no gerenciador de senhas pelo TP-0132. Nada de código novo.
**Camada:** só `wrangler.jsonc` (item de topo, SDD §2). Artefatos externos `cloudflare-conta` e `hyperdrive-configs`.
**Referência visual:** não se aplica.

Roteiro:
1. Painel Cloudflare → Workers & Pages → subdomínio da conta = `gestaodapelada`; se indisponível, `gestao-pelada`, depois `peladaapp` (ADR-010 §1). Se cair numa alternativa, registrar em `## 4` e sinalizar ao Coordenador (muda URL_PUBLICA e o ADR-010).
2. Conferir que a conta está no plano Workers **Free** (sem Workers Paid) — G-13.
3. Token de API (My Profile → API Tokens → Custom): permissões de conta `Workers Scripts: Edit` e `Hyperdrive: Edit`, recurso = só esta conta, sem zona; TTL opcional. Valor direto para o gerenciador de senhas (vai ao GitHub no TP-0134). Anotar o Account ID (não é segredo, mas vai como secret no TP-0134).
4. Criar os Hyperdrive com o usuário autenticado (`pnpm exec wrangler login` ou o token em `CLOUDFLARE_API_TOKEN` exportado na sessão), lendo a string sem eco para não ir ao histórico: `read -rs NEON_APP && pnpm exec wrangler hyperdrive create pelada-prod --connection-string="$NEON_APP" --caching-disabled`; idem `pelada-teste` com a string do branch `teste`; `unset NEON_APP`. Strings do `pelada_app`, diretas (sem `-pooler`).
5. Ler `wrangler.jsonc` imediatamente antes e editar com `Edit`: id do `pelada-prod` no `hyperdrive[0].id` da raiz e bloco `hyperdrive` próprio dentro de `env.teste` com o id do `pelada-teste` (bindings não são herdados pelo ambiente). Manter `localConnectionString` (Postgres local). Ids do Hyperdrive não são segredo.
6. Evidência em `## 4`: `pnpm exec wrangler hyperdrive get <id>` dos dois, mostrando `caching.disabled: true` e host direto — cortar usuário/senha se a saída trouxer.

Não fazer: `wrangler deploy` (só no `deploy.yml`, G-15/TP-0135), token global/"Edit all", binding novo fora da lista fechada, cache do Hyperdrive ligado.

## 2. Plano de teste
- Rodar o teste de configuração do TP-0013 depois da edição (lista fechada de recursos, G-13): `pnpm --filter @pelada/api test -- config` (arquivo de teste do `wrangler.jsonc` criado no TP-0013) — deve passar com o bloco `hyperdrive` em `env.teste`; se falhar por esse bloco, é ajuste do teste do TP-0013 (registrar em `## 4`).
- `pnpm exec wrangler hyperdrive list` mostra exatamente `pelada-prod` e `pelada-teste`; `get` de cada um com cache desligado.
- Token: `curl -H "Authorization: Bearer $TOKEN" https://api.cloudflare.com/client/v4/user/tokens/verify` → `active`; conferir no painel que as permissões são só as duas.
- Checagens base do CI na raiz (Seção 1 do TASK.md): `pnpm lint` e a guarda de ID (`node backend/scripts/checagens/checar-ids-tarefa.mjs`) com código de saída em `## 4`.

## 3. Plano de validação de segurança
- G-21: nenhuma string do Neon nem token no `wrangler.jsonc`, no diff, em `## 4` ou no histórico do shell (`read -s` + `unset`); gitleaks do CI (TP-0003) não acusa nada no diff.
- G-17/ADR-014 §2: cache desligado nos dois Hyperdrive (conferido pelo `get`); origem é a string direta, com TLS.
- Menor privilégio: token só com Workers Scripts e Hyperdrive da conta; Hyperdrive usa `pelada_app`, nunca o dono nem `pelada_backup`.
- G-13: plano Free, nenhum recurso pago; diff do `wrangler.jsonc` só altera ids/bloco hyperdrive.
- Isolamento de ambientes: `pelada-teste` aponta para o branch `teste`, nunca para `main` (conferir o host no `get`).
