**Camada:** `backend/api/src/aplicacao/pesos/salvar.ts` (`salvarPesos`) → `aplicacao`; `backend/api/src/entrada/rotas/grupos/pesos/salvar.ts` (rota fina) → `entrada`; uma linha em `src/entrada/app.ts` (reler antes).
**Referência visual:** não se aplica.

1. TDD (Seção 2) primeiro.
2. Rota `POST /api/grupos/:grupoId/pesos`: corpo por `NovosPesosCorpo` → falha = 422 `validacao` com `campos` (mensagem dos limites, forma de `erro-validacao-pesos.json`); campo extra (`vigenteDesde`, `grupoId`) → 422 pelo strict.
3. `salvarPesos(db, grupoId, { pesos, contaId, hoje, agora })` em `emTransacao`: `pesos.criar(tx, …, vigenteDesde: hoje)` + `auditoria.registrar(tx, grupoId, { autor: { tipo: 'conta', contaId }, acao: substituiu ? 'pesos_substituidos' : 'pesos_configurados', entidade: 'config_pesos', entidadeId: hoje, resumo: { pesos }, agora })`. `hoje`/`agora` do relógio (G-06); vigência nunca vem do cliente (RF-23).
4. `VigenciaNoPassado` não é alcançável pela rota (vigência = hoje); se ocorrer, é erro interno (500), não 422.
5. Resposta 200 com `montarPainelPesos(db, grupoId, hoje)` validado por `PainelPesos` (forma de `pesos-salvo.json`). Interpretação a registrar em `## 4`: 200 (a mesma forma do GET, arquivo sem status).
6. `casos.ts`: `POST /api/grupos/:grupoId/pesos` → `tipo: 'grupo'`, corpo válido (5 pesos padrão) para o 404 vir do middleware.
7. Não fazer: alterar configurações anteriores (RN-04); recalcular/guardar ranking (é calculado na leitura, ADR-006).
