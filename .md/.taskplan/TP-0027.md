## 1. Plano de execução
**Reaproveitamento:** USAR `ExecutorDb`/desembrulho interno de `backend/api/src/infraestrutura/db/` (TP-0014) e as tabelas tipadas em `tipos.ts` (TP-0025); `criarFabrica`/`usarFabrica` de `backend/api/test/apoio/fabrica.ts`, `relogioFixo` (TP-0017) e `test/apoio/sql.ts` (TP-0025) na limpeza. `infraestrutura/seguranca/` já existe com `trava-host.ts` (TP-0015): acrescentar arquivos ao lado, sem mexer nele. Normalização de e-mail: a do `contrato/base` (TP-0005) — o repositório recebe e-mail já normalizado, não normaliza de novo.
**Camada:** `backend/api/src/infraestrutura/db/repositorios/contas.ts` (módulo de dados; único lugar com `crypt`, G-02); `backend/api/src/infraestrutura/seguranca/{token.ts,senha-temporaria.ts,index.ts}` (infraestrutura; importável por `backend/scripts`, L-2); fábrica `backend/api/test/apoio/fabricas/contas.ts`.
**Referência visual:** não se aplica.

1. `seguranca/token.ts`: `gerarTokenSessao()` → 32 bytes de `crypto.getRandomValues` em base64url; `hashToken(token)` → `Uint8Array` de 32 bytes via `crypto.subtle.digest('SHA-256')` (casa com `sessoes.token_hash bytea`).
2. `seguranca/senha-temporaria.ts`: `gerarSenhaTemporaria()` → 12 caracteres de alfabeto sem ambíguos (sem `0 O o 1 l I`, ADR-015 §5), rejeição de viés (descarta byte ≥ `floor(256/n)*n`). Alfabeto exportado como constante para o teste.
3. `repositorios/contas.ts` (assinaturas na convenção do TP-0014: executor 1º; contas não é dado de grupo → entrada "arquivo inteiro" em `backend/scripts/checagens/grupo-id-excecoes.json`, TP-0016):
   - `buscarPorEmail(db, email)` → `{ id, email, nome, senhaTemporaria, eDono, avisoPrivacidadeVistoEm } | null` (nunca devolve `senha_hash`); `buscarPorId(db, contaId)` idem.
   - `criar(db, { email, nome, senha, senhaTemporaria, agora })` → id; hash `crypt($senha, gen_salt('bf', 12))` com a senha só como parâmetro; **não aceita `eDono`** (G-11).
   - `verificarSenha(db, email, senha)` → `{ contaId, senhaTemporaria } | null` numa só consulta: `FROM (SELECT $email) e LEFT JOIN contas c USING (email)` e `crypt($senha, coalesce(c.senha_hash, $HASH_FIXO)) = coalesce(c.senha_hash, $HASH_FIXO)` → mesmo bcrypt de custo 12 com ou sem conta (ADR-015 §4). `HASH_FIXO` = constante bcrypt `$2a$12$…` gerada uma vez de valor aleatório (não é segredo).
   - `trocarSenha(db, contaId, novaSenha, { temporaria })` → grava hash e `senha_temporaria`.
   - `marcarAvisoVisto(db, contaId, agora)` idempotente (`coalesce(aviso_privacidade_visto_em, $agora)`).
4. Nenhum `console.*` no repositório; erro do `pg` relançado sem anexar parâmetros. Senha em `sql` só via parâmetro (`sql\`crypt(${senha}, …)\`` do Kysely parametriza; nunca `sql.raw`).
5. Fábrica `criarConta({ temporaria? })` usando `criar` e registrando a limpeza (apaga sessões/pedidos/auditoria da conta antes da conta).

Não fazer: bloqueio por tentativas (TP-0028/TP-0034), redefinição de senha (TP-0037), escrita de `e_dono` (TP-0041).

## 2. Plano de teste
Vitest no pool de Workers + Postgres (TP-0017), `backend/api/test/repositorios/contas.test.ts` e `test/infraestrutura/seguranca.test.ts`:
- verificar: senha certa → conta; errada → null; e-mail inexistente → null; senha de 72 bytes vs. mesma +1 byte (documenta o corte do bcrypt; o limite é do contrato, L-15).
- mesmo custo: medir 5 verificações com e-mail existente e 5 com inexistente; mediana na mesma ordem de grandeza (razão < 1,5) e `EXPLAIN`/contagem confirmando que `crypt` roda nos dois caminhos.
- `criar` grava `senha_hash` começando com `$2a$12$`; `trocarSenha` marca/desmarca `senha_temporaria` e a senha antiga deixa de valer; `marcarAvisoVisto` duas vezes mantém o 1º momento (relógio fixo).
- `buscarPorEmail` não tem `senhaHash` no objeto (teste de chaves).
- log sem a senha: espionar `console.*` durante criar/verificar/trocar e num erro forçado (e-mail duplicado) — nenhuma saída contém a senha.
- seguranca: token com 43 caracteres base64url e 1000 tokens distintos; `hashToken` igual ao vetor conhecido de SHA-256; senha temporária com 12 caracteres, só do alfabeto, sem ambíguos; viés: `getRandomValues` falso devolvendo bytes ≥ limite → descartados (teste determinístico).
Comando: `pnpm --filter @pelada/api test -- contas seguranca` + `node backend/scripts/checagens/checar-grupo-id.mjs`.

## 3. Plano de validação de segurança
- G-02/ADR-015: `crypt` só em `repositorios/contas.ts`; senha sempre parâmetro (procurar `sql.raw` e concatenação no diff); custo 12; nenhuma lib de hash no Worker (G-08).
- Enumeração de conta: mesmo custo e mesmo retorno (`null`) para e-mail inexistente e senha errada.
- Sem senha, hash ou token em log, erro ou objeto de retorno (G-08); `senha_hash` nunca sai do módulo.
- G-11: nenhuma função escreve `e_dono`.
- Aleatoriedade só de `crypto.getRandomValues`/WebCrypto (nada de `Math.random`); token de 256 bits, banco guarda só o SHA-256 (ADR-003).
