No teste "sem configuração financeira: só a marcação, nenhum lançamento" (linha 57) aparece o lançamento "Mensalidade Ana 10/2026" (7500). Descobrir se é o código (config padrão/mensalidade herdada) ou dado residual do pelada_teste; corrigir o ponto certo. Não é a RTP-0111 (colisão contas_email_unico).

`vitest run pagamentos-marcar` (backend/api).

## 4. Resultado da execução
Causa: bug do próprio teste, não do código nem de dado residual. `cenario(comMensalidade: boolean | undefined = true)` — passar `undefined` aciona o valor padrão `true`, então o teste "sem configuração financeira" gravava config com mensalidade 7500. Código de produção (`marcarPagamento`, `entradaDaMensalidade`, `lerConfig`) já se comportava certo (sem config => `null` => sem lançamento).
Correção: parâmetro passou a `boolean | null` (`null` = não grava config) e o teste chama `cenario(null)`. Arquivo alterado: `backend/api/test/rotas/grupos/financeiro/pagamentos-marcar.test.ts`.
