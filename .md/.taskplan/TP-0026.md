# TP-0026 — Migração do contexto Grupos (grupos, vínculos de admin)

Reserva: Livre
ID no TASK.md: TP-0026 · Lote: L06 · Agente: executor · Chapéu: Backend · Est: 0,5 d · Dep: TP-0015, TP-0016, TP-0025 · Status no TASK.md: Pendente
Reqs: SDD §5; ADR-016; RN-13; RF-04 · Aceite: Grupos (nome, slug único, dia_semana, frequencia, horario, situacao_comercial padrão `uso_proprio`, trial_inicio, arquivado_em, criado_por/em) com gatilho que recusa UPDATE do slug; vinculos_admin (conta, grupo, acessa_financeiro, criado_por/em; único por conta e grupo). Testes: slug imutável, vínculo duplicado recusado

## 1. Plano de execução
**Reaproveitamento:** USAR `aplicarMigracoes`/pasta `migracoes/` (TP-0015), `checar-migracao-aditiva.mjs` (TP-0016), o `globalSetup` (TP-0017), a tabela `contas` da migração de Acesso (TP-0025), `TabelasBanco` em `infraestrutura/db/tipos.ts` (TP-0014/TP-0025) e o `backend/api/test/apoio/sql.ts` para SQL cru em teste (criado/extraído no TP-0025). Valores de enum iguais aos de `backend/contrato/src/enums.ts` (TP-0005).
**Camada:** `backend/api/src/infraestrutura/db/migracoes/<AAAAMMDDHHMM>_grupos.sql` (carimbo **posterior** ao de `_acesso.sql`) e `infraestrutura/db/tipos.ts` → módulo de dados (G-02); teste em `backend/api/test/migracoes/grupos.test.ts`.
**Referência visual:** não se aplica.

1. `grupos`: `id uuid PK default gen_random_uuid()`, `nome text` 3 a 60 (`CHECK char_length`), `slug text NOT NULL UNIQUE CHECK (slug ~ '^[a-z0-9-]{1,64}$')` (Seção 1.4), `dia_semana text CHECK IN (domingo…sabado)`, `frequencia text CHECK IN ('semanal','quinzenal','mensal')`, `horario time NOT NULL`, `situacao_comercial text NOT NULL DEFAULT 'uso_proprio' CHECK IN (uso_proprio, trial, ativo, inadimplente, cancelado)`, `trial_inicio date NULL` com `CHECK ((situacao_comercial = 'trial') = (trial_inicio IS NOT NULL))` (RN-16, igual ao `refine` do `contrato/dono`), `arquivado_em timestamptz NULL`, `criado_por uuid NOT NULL` FK contas, `criado_em timestamptz NOT NULL` (sem `now()`, vem do relógio).
2. Gatilho `grupos_slug_imutavel` (`BEFORE UPDATE OF slug`, função plpgsql): `NEW.slug IS DISTINCT FROM OLD.slug` → `RAISE EXCEPTION` com SQLSTATE próprio. Slug nunca reutilizado (ADR-016 §5): grupos não são apagados (só arquivados) — nenhuma migração/repositório cria DELETE.
3. `vinculos_admin`: `conta_id` FK contas, `grupo_id` FK grupos, `acessa_financeiro boolean NOT NULL DEFAULT false`, `criado_por uuid NOT NULL` FK contas, `criado_em timestamptz NOT NULL`; `PRIMARY KEY (conta_id, grupo_id)`; índice por `grupo_id` (admins do grupo, contagem do RN-13).
4. RN-13 (pelo menos 1 admin) **não** é regra de banco: fica na transação de remoção (TP-0065); não criar gatilho para isso.
5. Acrescentar `grupos` e `vinculos_admin` em `TabelasBanco`.
6. Atenção: o corpo `$$…$$` do gatilho passa pelo `checar-migracao-aditiva` (strings dollar-quoted são ignoradas); conferir que fica verde.

## 2. Plano de teste
`backend/api/test/migracoes/grupos.test.ts` (pool de Workers + Postgres; apaga o que cria em `afterEach`, mesmo em falha; momentos de `relogioFixo`):
- slug imutável: UPDATE do slug → erro do gatilho; UPDATE do nome no mesmo grupo → aceito e slug intacto; UPDATE com o mesmo slug → aceito.
- slug duplicado (inclusive grupo arquivado) → `23505`; slug `Abc`, `a b`, 65 caracteres → recusados.
- vínculo duplicado (conta, grupo) → `23505`; `acessa_financeiro` padrão `false`.
- situação `trial` sem `trial_inicio` e `ativo` com data → recusados; padrão `uso_proprio`.
- `dia_semana`/`frequencia` fora do enum, nome com 2 e 61 caracteres → recusados.
- `checar-migracao-aditiva.mjs` verde.
Comando: `pnpm --filter @pelada/api test -- migracoes/grupos` + a checagem.

## 3. Plano de validação de segurança
- ADR-016/G-03: slug imutável e único no banco (gatilho + índice), base do "nunca mostrar outro grupo pelo link antigo".
- ADR-005: `vinculos_admin` é a fonte da autorização por grupo; chave (conta, grupo) única. Nenhuma coluna de papel global aqui (`e_dono` só em contas, G-11).
- G-14: migração aditiva; nada de dado pessoal novo (LGPD).
