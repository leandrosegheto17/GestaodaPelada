## 2. Plano de teste
- Checagem (matriz adversarial, CONVENCOES §9): `INSERT INTO contas (…, e_dono)` numa rota → falha; `UPDATE contas SET e_dono = true` em várias linhas e caixa mista (`E_DONO`, `"e_dono"`) → falha; `.set({ e_dono: true })`, `.values({ eDono })`, chave calculada `['e_' + 'dono']` → falha; `e_dono` em comentário ou em string de mensagem → passa; `WHERE e_dono` / `select('e_dono')` → passa; mesmo INSERT dentro de `backend/scripts/` e de migração → passa; arquivo ilegível, pasta ausente, `git ls-files` falhando → falha fechado; repositório real → verde.
- Script (Postgres local, trava passando; fábricas apagam a conta do dono e as auditorias criadas): `criar` com e-mail digitado certo → conta `e_dono`, temporária, 1 auditoria "infraestrutura", senha aparece 1 vez no stdout; digitado errado/caixa diferente antes de normalizar → conforme regra, sem nada gravado; `criar` de novo → recusa; `redefinir-senha` → senha nova vale, antiga não, sessões do dono encerradas; `DONO_EMAIL` ausente/inválido → código 1; host remoto sem `--alvo` → recusa antes de conectar; `--alvo producao` sem CI e sem confirmação do host → recusa.
- Comandos: testes da checagem/script (conforme PENDENTE 3), `node backend/scripts/checagens/checar-escrita-e-dono.mjs` na raiz, `pnpm lint` (fronteira de `backend/scripts`).
