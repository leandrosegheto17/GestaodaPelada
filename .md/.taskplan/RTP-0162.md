# RTP-0162 — deploy.yml: lógica do branch de restauração do Neon em script testado (hoje `node -e` inline)

Reserva: Livre
ID no TASK.md: RTP-0162 · Lote: Refatoração Revisão 2026-10-19 · Agente: executor · Chapéu: Backend · Est: 0,4 d · Dep: - · Status no TASK.md: Pendente
Reqs: ADR-011; SDD §6 "Troca de dados em produção"; CONVENCOES-DE-CODIGO (lógica testável fora do YAML) · Aceite: o passo "Branch de restauração no Neon" do `deploy.yml` não tem mais `node -e` com JSON inline; achar o branch pai e escolher quais branches `restauracao-<ambiente>-*` apagar (manter os 2 mais novos) ficam em função pura testada em `backend/scripts/ops/`, chamada por CLI fina; testes cobrem pai ausente (falha fechado), lista vazia, 0/1/2/3+ branches e ordenação por `created_at`; `pnpm` lint/typecheck e `checar-*` em 0

## 1. Plano de execução
Achado (item 17, CI / troca de dados em produção, severidade Média): `.github/workflows/deploy.yml:46` e `:52` têm dois one-liners `node -e` que decidem qual branch do Neon é o pai e **quais branches de produção são apagados** (DELETE). É lógica destrutiva sem teste, em YAML, enquanto o resto do mesmo workflow já segue o padrão "regra em script testado" (`hyperdrive-id.ts`, `verificar-cache-hyperdrive.ts` + CLI). Um erro de ordenação ou de prefixo apaga o branch de restauração errado exatamente no deploy que precisa dele.

**Reaproveitamento:** seguir o par já existente em `backend/scripts/ops/` (`verificar-cache-hyperdrive.ts` com função pura + `...-cli.ts` de uma linha; teste em `ops/test/`). Criar `restauracao-neon.ts` com `idDoBranchPai(corpo, nome)` e `branchesAntigos(corpo, ambiente, manter = 2)` (mesma regra de hoje, falhando fechado se JSON inválido ou pai ausente) e uma CLI fina que lê stdin; trocar os dois `node -e` por `pnpm --silent exec tsx` dessa CLI. O `curl` com o token continua no YAML. Não alterar a regra (prefixo, 2 mais novos) nem o resto do workflow.

## 2. Plano de teste
Vitest em `backend/scripts/ops/test/restauracao-neon.test.ts`: pai achado/ausente/JSON inválido; 0, 1, 2, 3 e 5 branches `restauracao-producao-*` (só os mais velhos saem); branches de outro prefixo ou ambiente nunca listados; ordenação por `created_at`. `checar-wrangler-deploy.mjs` e `checar-urls-absolutas.mjs` seguem em 0 (a URL do Neon continua só no YAML).

## 3. Plano de validação de segurança
Token do Neon continua só em env e cabeçalho do `curl` (não vai a argv do script novo nem a log); a CLI não ecoa o corpo da resposta ao falhar; nunca lista branch fora do prefixo `restauracao-<ambiente>-` (proteção do branch `production`).
