# TP-0091 — Cliente da API no web (`src/dados`)

Reserva: Livre
ID no TASK.md: TP-0091 · Lote: L20 · Agente: executor · Chapéu: Frontend · Est: 1 d · Dep: TP-0088, TP-0005 · Status no TASK.md: Pendente
Reqs: C1; ADR-003; UX-SPEC §4; CONVENCOES §8 · Aceite: `fetch` relativo a `/api`, `X-Pelada: 1` nas escritas, resposta validada pelo schema do contrato, erro padrão tipado, 401 em rota de admin → `/entrar?destino=`; `QueryClient` sem retry em 4xx e com 1 retry em erro de rede. Testes com API falsa (msw)

## 1. Plano de execução
**Reaproveitamento:** USAR de `@pelada/contrato` (TP-0005, `backend/contrato/src/erro.ts`) o schema de erro padrão e as constantes de código (`nao_autenticado`, `erro_interno`…) — não redefinir a forma do erro no web. USAR `src/app/App.tsx` de TP-0088 (troca o `QueryClient` padrão pelo configurado aqui) e `msw` instalado por TP-0088 (se ausente, instalar e registrar lockfile).
**Camada:** `@pelada/web` → `src/dados/` (SDD §2); alteração mínima em `src/app/App.tsx`.
**Referência visual:** não se aplica.

1. `src/dados/erros.ts`: `ErroApi` (`status`, `codigo`, `mensagem`, `campos?`, extras do contrato preservados), `ErroRede` (fetch rejeitou / abortado por falha) e `ErroResposta` (corpo não confere com o schema, ou erro sem a forma padrão — ex.: HTML de 429/502 da Cloudflare); helper `ehErroDeRede(e)`.
2. `src/dados/cliente.ts`: `ler(caminho, schema, { signal })` e `escrever(metodo, caminho, corpo, schema)`:
   - `caminho` tem de começar com `/` e não com `//` (senão erro de programação); URL = `new URL('/api' + caminho, location.origin)` (mesma origem, nada absoluto no código, ADR-010);
   - `credentials: 'same-origin'`; escrita (POST/PUT/PATCH/DELETE) com `Content-Type: application/json` e `X-Pelada: 1` (ADR-003, G-09);
   - 204 → `undefined` validado por schema vazio; 2xx → `schema.parse(json)` (falha → `ErroResposta`); não-2xx → `ErroApi` se o corpo passa no schema de erro, senão `ErroResposta` com o status.
   - Nenhum log do corpo da resposta nem da requisição (pode ter telefone/senha).
3. `src/dados/destino.ts`: `destinoDeEntrada(pathname, search)` → `/entrar?destino=<encodeURIComponent(pathname+search)>` quando a página atual é de admin (`/admin`, `/conta`, `/dono` e subrotas), `null` nas públicas (`/`, `/g/…`) e em `/entrar…` (evita laço).
4. `src/dados/consultas.ts`: `criarClienteConsultas({ aoNaoAutenticado })` — `retry` das consultas: 1 tentativa só para `ErroRede`, 0 para `ErroApi`/`ErroResposta`; `QueryCache`/`MutationCache` `onError`: `ErroApi` 401 chama `aoNaoAutenticado()`.
5. `App.tsx`: `aoNaoAutenticado` = `destinoDeEntrada(location…)` → `router.navigate(destino, { replace: true })` quando não for `null`.

PENDENTE: o aceite fala de 4xx e erro de rede; e 5xx e mutações? Proposta: 5xx sem retry (erro de CPU/1102 do Worker não melhora repetindo, UX-SPEC §7) e mutações sem retry automático (POST repetido após falha de rede pode duplicar lançamento/partida; o "Tentar de novo" é do usuário). Confirmar.

NÃO fazer: ganchos por contexto (cada tela/`web/sessao` cria os seus usando `ler`/`escrever`); guarda de rotas (TP-0105).

## 2. Plano de teste
Vitest + `msw/node` (`setupServer`, handlers relativos a `/api`, ambiente jsdom de TP-0088), em `src/dados/*.test.ts`:
- `cliente`: GET com resposta válida → objeto parseado; resposta com campo de tipo errado → `ErroResposta`; POST/PUT/PATCH/DELETE levam `X-Pelada: 1` e `Content-Type`, GET não leva `X-Pelada`; URL chega como `/api/...` na mesma origem; caminho `//evil.com/x` e `x` sem barra → erro antes do fetch; 204 → `undefined`; 422 `respostas/erro-validacao.json` → `ErroApi` com `campos`; 401 `erro-nao-autenticado.json` → `ErroApi` 401; 500 com HTML → `ErroResposta` status 500; `HttpResponse.error()` → `ErroRede`; `signal` abortado não vira `ErroRede` retentável.
- `consultas`: contagem de chamadas no msw — erro de rede → 2 chamadas; 404/422/401 → 1; 500 → 1 (conforme PENDENTE); 401 chama `aoNaoAutenticado` uma vez (consulta e mutação).
- `destino`: `/admin/g-quinta/partidas?mes=2026-10` → `destino=%2Fadmin%2Fg-quinta%2Fpartidas%3Fmes%3D2026-10`; `/conta/senha`, `/dono` → destino; `/g/pelada-de-quinta`, `/`, `/entrar`, `/entrar/nova-senha` → `null`; `/administracao` (prefixo falso) → `null`.
- Fixtures: os JSON de `.md/mockup/respostas/` lidos do disco (sem dado escrito à mão). Comando: `pnpm --filter @pelada/web test -- src/dados`.

## 3. Plano de validação de segurança
- G-09/ADR-003: `X-Pelada: 1` em toda escrita (teste por método); nenhum acesso a `document.cookie` (lint do TP-0002); cookie só via `same-origin`.
- Open redirect: o destino é sempre caminho local montado a partir de `location` e codificado; o leitor do `destino` (T04/TP-0105) ainda precisa validar `/` inicial sem `//`.
- CONVENCOES §8: resposta validada pelo contrato antes de chegar à tela; erro fora da forma padrão não é exibido como mensagem (evita refletir HTML/texto arbitrário).
- G-08/LGPD: nenhum log de corpo; mensagens de erro técnicas não aparecem ao usuário.
