# TP-0016 — Guardas do banco no CI: migração aditiva e `grupoId` nos repositórios

Reserva: Livre
ID no TASK.md: TP-0016 · Lote: L03 · Agente: executor · Chapéu: Backend · Est: 1 d · Dep: TP-0015, TP-0003 · Status no TASK.md: Pendente
Reqs: SDD §6; ADR-005; ADR-012; CONVENCOES §9; G-03, G-07, G-14 · Aceite: `checar-migracao-aditiva.mjs` falha em DROP, RENAME, ALTER … TYPE, SET NOT NULL sem default e nos tipos `money`, `real`, `double precision`, `float`, `numeric` de valor, salvo linha `-- contrair: <motivo>`; `checar-grupo-id.mjs` (API do compilador TS) falha se função exportada de repositório de dado de grupo não tem `grupoId` como 1º parâmetro (lista de exceções do dono explícita). Passos no `ci.yml`. Matriz adversarial: comentário de linha e de bloco, string literal com DROP, caixa mista, comando quebrado em linhas, arquivo vazio, leitura falhando (falha fechado)

## 1. Plano de execução
**Reaproveitamento:** USAR o padrão e o utilitário das checagens do TP-0002 em `backend/scripts/checagens/` (`checar-ids-tarefa.mjs`, `checar-urls-absolutas.mjs`): se a listagem de arquivos/saída/código de erro estiver dentro de um deles, EXTRAIR para `backend/scripts/checagens/comum.mjs` e usar nos quatro. USAR a pasta `backend/api/src/infraestrutura/db/migracoes/` (TP-0015) e o job base do `.github/workflows/ci.yml` (TP-0003). `typescript` já é devDependency da raiz (TP-0001).
**Camada:** `backend/scripts/checagens/` (scripts de CI, fora dos pacotes); testes ao lado dos do TP-0002 (mesma convenção).
**Referência visual:** não se aplica.

1. `checar-migracao-aditiva.mjs [dir]` (padrão: `migracoes/`):
   - Primeiro procura a linha `-- contrair: <motivo>` (motivo não vazio) — isenta o arquivo inteiro.
   - Depois normaliza: remove comentário `--` e `/* */` (aninhado, como no Postgres), strings `'…'` (com `''`), `E'…'`, dollar-quoted `$$…$$`/`$tag$…$tag$` e identificadores entre aspas; colapsa espaços e quebras; minúsculas.
   - Recusa: `\bdrop\b`, `\brename\b`, `alter column … (set data )?type`, `set not null` sem `default` para a mesma coluna no arquivo, tipos `money`, `real`, `double precision`, `float(n)?`/`float4`/`float8`.
   - Arquivo vazio (ou só comentário), arquivo ilegível, pasta ausente → falha fechado. Pasta vazia → passa ("0 migrações").
2. `checar-grupo-id.mjs`: `ts.createProgram` sobre `backend/api/src/infraestrutura/db/repositorios/**/*.ts` (sem testes); para cada símbolo exportado (via `checker.getExportsOfModule`, cobre `export function`, `export const f = () =>`/`function`, `export { a as b }`, `export default`, `export * from`), resolve a declaração e exige o parâmetro `grupoId` na posição definida (ver PENDENTE). Parâmetro desestruturado, `rest`, nome diferente (`grupo_id`, `idGrupo`, `grupoID`) → falha. Exceções em `backend/scripts/checagens/grupo-id-excecoes.json` (`{ arquivo, funcao?, motivo }`; arquivo inteiro para repositórios que não são dado de grupo — contas, sessões, tentativas, pedidos; funções do dono em grupos/vínculos). Exceção sem correspondência → falha (lista não apodrece). Erro de sintaxe/diagnóstico, `typescript` ausente, pasta ausente → falha fechado.
3. Criar `repositorios/.gitkeep` se ainda não existir (para o CI ficar verde antes do 1º repositório).
4. `ci.yml`: dois passos no job base (não precisam de banco), depois do lint.

DECIDIDO (Coordenador): proposta aceita: ignora o 1º parâmetro quando é o executor do módulo de dados (`Db`/`Tx`/`ExecutorDb`) e exige `grupoId` logo depois. Pergunta original: posição do `grupoId` — aceite diz 1º parâmetro, a Seção 1.2 do TASK usa `partidas.criar(tx, grupoId, …)`. Proposta: ignorar o 1º parâmetro quando o tipo é o executor do módulo de dados (`Db`/`Tx`/`ExecutorDb` do TP-0014) e exigir `grupoId` logo depois. Confirmar.
DECIDIDO (Coordenador): recusar `numeric`/`decimal` em qualquer coluna (isenção só pela linha `-- contrair:`) E recusar `ADD COLUMN … NOT NULL` sem `DEFAULT`. Pergunta original: "`numeric` de valor" não é decidível pela sintaxe. Proposta: recusar `numeric`/`decimal` em qualquer coluna (o SDD §5 não tem uso legítimo; tudo é inteiro), com isenção só pela linha `-- contrair:`. E incluir `ADD COLUMN … NOT NULL` sem `DEFAULT` (mesmo risco do SET NOT NULL)? Confirmar.

## 2. Plano de teste
Testes com fixtures em pastas temporárias (criadas e apagadas pelo teste), rodando o script como processo (código de saída + mensagem com arquivo e linha):
- aditiva — passa: `CREATE TABLE` com `integer`/`bigint`, `ADD COLUMN` nulo, `-- drop` em comentário, `/* DROP TABLE x */`, `'DROP TABLE'` em string, `$$ … DROP … $$` em função, coluna chamada `"drop"`, arquivo com `-- contrair: remover coluna antiga após deploy X` + DROP. Falha: `DROP TABLE`, `drop   \n table`, `DrOp`, `ALTER TABLE t RENAME TO u`, `RENAME COLUMN`, `ALTER COLUMN c TYPE bigint`, `SET DATA TYPE`, `SET NOT NULL` sem default, `money`, `REAL`, `double\nprecision`, `float8`, `numeric(10,2)`, `-- contrair:` sem motivo, comentário de bloco aninhado mal fechado escondendo DROP, arquivo vazio, arquivo sem permissão de leitura/caminho inexistente.
- grupo-id — passa: `export async function listar(exec, grupoId, …)` (conforme a resposta do PENDENTE), exceção válida. Falha: `grupoId` em 2ª posição de negócio, sem parâmetros, desestruturado `{ grupoId }`, `...args`, `export const f = (id, grupoId) =>`, `export { f as g }` de função errada, `export * from './interno'` com função errada, `export default`, exceção obsoleta, arquivo com erro de sintaxe, pasta ausente.
- Testes `ts`/`mjs` conforme o runner do TP-0002. Comando: `pnpm -r test -- checagens` e `node backend/scripts/checagens/checar-migracao-aditiva.mjs && node backend/scripts/checagens/checar-grupo-id.mjs` na raiz (verdes no repositório atual).
