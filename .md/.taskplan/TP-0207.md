## 1. Plano de execução
**Reaproveitamento:** USAR `src/estilos/tokens.css` e `global.css` (TP-0088), `Icone` e os básicos do TP-0095. Nada a extrair.
**Camada:** `@pelada/web` → `frontend/web/src/componentes/pagina/` (SDD §2, `src/componentes`), um componente por arquivo + `index.ts`.
**Cria:** `Voltar` (aceita `para` — vira `Link` — ou `aoClicar` — vira `button`; seta pelo `Icone`), `TituloPagina`, `Subtitulo`, `Secao`, `Cartao`, `Paragrafo`, `GrupoBotoes`, `Formulario`, `DuasColunas`, `FerramentasLista`, `ConteudoPagina` (variação estreita `conteudo--estreito`, para páginas fora do `LayoutAdmin`: T04–T07, T25, T27).
**Passos:**
1. Para cada componente, ler no mockup o markup/classes correspondentes e copiar o CSS de `.md/mockup/base.css` (linhas 40–65, 95 e 140) para o CSS Module, trocando valores literais por variáveis de `tokens.css`.
2. Componentes só apresentam: sem fetch, sem rota própria, sem regra de negócio, sem estilo em linha, sem `dangerouslySetInnerHTML`.
3. O `conteudo--estreito` do admin continua vindo do `handle` do `LayoutAdmin` (TP-0106); `ConteudoPagina` serve às páginas fora do layout.
4. Registrar em `## 4` o mapa classe do mockup → componente, para as telas consumirem.

## 2. Plano de teste
- Um arquivo de teste por componente (ou agrupado por afinidade) em `frontend/web/src/componentes/pagina/`, Testing Library: renderiza com as classes/markup do mockup; `Voltar` com `para` renderiza `a` e com `aoClicar` renderiza `button` (clicável por teclado); `ConteudoPagina` aplica a variação estreita.
- `axe-core` sem violação em cada componente.
- `stylelint` verde nos CSS Modules; nenhum valor literal de cor/espaçamento fora de `tokens.css`.
- Rodar com `npx vitest run src/componentes/pagina --no-file-parallelism`.

## 3. Plano de validação de segurança
Sem dado pessoal e sem dependência nova. Conferir: nenhum `dangerouslySetInnerHTML`/`innerHTML`/`style=`; links de `Voltar` só por `Link` do React Router (sem URL absoluta); sem `console`; sem ID de tarefa nos comentários.
