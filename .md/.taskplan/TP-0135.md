# TP-0135 — Workflow de deploy (`deploy.yml`)

Reserva: Livre
ID no TASK.md: TP-0135 · Lote: L30 · Agente: executor · Chapéu: Backend · Est: 1 d · Dep: TP-0134, TP-0015, TP-0013, TP-0003, TP-0133 · Status no TASK.md: Pendente
Reqs: ADR-014 §6; ADR-011 §2; SDD §3 (CI/CD), §6; G-15, G-17 · Aceite: Push na `main` (environment `producao`) e disparo manual (`teste`): 1) branch de restauração no Neon pela API + dump cifrado como artefato; 2) `migrar.ts --alvo`; 3) `wrangler hyperdrive get` confere o cache desligado; 4) `wrangler deploy` com URL_PUBLICA e `VITE_RECURSOS_DESLIGADOS` do ambiente; falha depois da migração → `wrangler rollback` e instrução de restauração no log. Passo no `ci.yml` falha se `wrangler deploy` aparece fora deste workflow. Evidência: execução manual em `teste` verde e `GET /api/saude` 200 em `pelada-teste`

## 1. Plano de execução
**Reaproveitamento:** USAR a action composta de dump cifrado `.github/actions/dump-cifrado/action.yml` criada pelo TP-0136 (pg_dump na versão do servidor + cifra age + upload de artefato) — não escrever outro dump aqui; `backend/scripts/migrar.ts` e a trava `--alvo`/`CI=true` (TP-0015); `wrangler.jsonc` com `env.teste` = `pelada-teste` e os ids de Hyperdrive gravados pelo TP-0133; setup pnpm/node com cache do job `base` do `ci.yml` (TP-0003) — se o setup estiver inline no `ci.yml`, EXTRAIR para `.github/actions/preparar-node/action.yml` e usar nos dois workflows; utilitário de listagem/saída `backend/scripts/checagens/comum.mjs` (TP-0002/TP-0016) na checagem nova; `lerRecursosDesligados` do build (TP-0088) já falha com nome inválido.
**Camada:** `.github/workflows/deploy.yml`, `.github/actions/*` (item de topo `.github/`, SDD §2); `backend/scripts/checagens/checar-wrangler-deploy.mjs` + teste (checagens de CI); passo novo no job `base` do `ci.yml`; seção "Deploy" no `backend/README.md` (o runbook completo é do TP-0137).
**Referência visual:** não se aplica.

1. TDD: testes da checagem primeiro (§2). `checar-wrangler-deploy.mjs`: em arquivos versionados executáveis (`.github/**/*.yml`, `package.json` (campo `scripts`), `*.sh`, `*.{js,mjs,cjs,ts}`), fora de `.github/workflows/deploy.yml` e do próprio checador/teste, falha se aparecer `wrangler … deploy` ou `wrangler versions deploy` (com `npx`/`pnpm exec`/`pnpm dlx`/`wrangler@x`, espaços múltiplos, quebra `\`). Markdown não é varrido (o `DEPLOY.md` documenta o comando). Falha fechado se `git ls-files` falhar.
2. `deploy.yml`: `on: push: branches [main]` + `workflow_dispatch` com input `ambiente` (choice só `teste`); `ambiente = github.event_name == 'push' && 'producao' || 'teste'`; `environment: ${{ ambiente }}` (aprovação manual em `producao`, TP-0134); `concurrency: deploy-<ambiente>` sem cancelar; `permissions: contents: read`; secrets escolhidos por ambiente (`NEON_URL_MIGRACAO_PROD`/`_TESTE`); `URL_PUBLICA` e `VITE_RECURSOS_DESLIGADOS` de `vars` do environment (sem valor no repositório).
3. Passo 1 — branch de restauração: `curl` na API v2 do Neon (`NEON_API_KEY`, `NEON_PROJECT_ID`): busca o id do branch pai (`main` ou `teste`) por nome, cria `restauracao-<ambiente>-<run_id>`; apaga os `restauracao-<ambiente>-*` além dos 2 mais novos (limite de branches do plano grátis). Depois, a action `dump-cifrado` com a string de migração do ambiente e artefato `dump-predeploy-<ambiente>-<run_id>` (30 dias).
4. Passo 2 — `pnpm exec tsx backend/scripts/migrar.ts --alvo <ambiente>` (ou o comando do README do TP-0015) com `CI=true` e `DATABASE_URL` do secret.
5. Passo 3 — `wrangler hyperdrive get <id do ambiente lido do wrangler.jsonc>` com saída JSON; falha se `caching.disabled` não for `true` (G-17). O id sai do `wrangler.jsonc` por `node -e` com o mesmo parser do teste de configuração do TP-0013, não repetido no YAML.
6. Passo 4 — `pnpm --filter @pelada/web build` com `VITE_RECURSOS_DESLIGADOS` do ambiente; `wrangler deploy [--env teste] --var URL_PUBLICA:<vars.URL_PUBLICA>`; depois `curl -fsS --retry 3 <URL_PUBLICA>/api/saude`.
7. Falha: passo `if: failure() && steps.migrar.outcome == 'success'` (ou falha do deploy/saúde) roda `wrangler rollback [--env teste]` só se o deploy chegou a publicar, e imprime a instrução de restauração com o nome do branch criado e o ponteiro para o `DEPLOY.md`. Falha antes da migração não toca nada.
8. Passo no job `base` do `ci.yml`: `node backend/scripts/checagens/checar-wrangler-deploy.mjs`; acrescentar o comando à lista de `## 4` (a Seção 1.6 do TASK.md não é editada aqui — registrar a divergência).
9. Evidência: disparo manual em `teste` verde + saúde 200 (URL do run em `## 4`; push e disparo só com permissão do usuário).

Não fazer: deploy por `wrangler` local; segredo em `run:` interpolado direto (usar `env:`); `pull_request_target`.
PENDENTE: o lote marca TP-0135 e TP-0136 como paralelos, mas a coluna "Dependentes" do TP-0136 lista o TP-0135 e os dois precisam do mesmo dump cifrado. Proposta: rodar o TP-0136 antes (ele cria `.github/actions/dump-cifrado`) e o TP-0135 só usa. Confirmar a serialização.

## 3. Plano de validação de segurança
- G-15: ordem branch → dump → migração → deploy garantida por `needs`/passos sequenciais; `producao` com aprovação manual; nenhum outro caminho para `wrangler deploy` (checagem no CI).
- G-21/SDD §7: segredos só em `secrets.*` via `env:`, nunca ecoados (sem `set -x`; string de conexão e chave jamais vão para o log, nem em mensagem de erro do `curl`/`psql`); `CLOUDFLARE_API_TOKEN` de escopo mínimo; o dump só sai cifrado.
- G-17: falha se o cache do Hyperdrive estiver ligado.
- `permissions: contents: read`; actions oficiais por versão maior; input `ambiente` restrito a `teste` (manual nunca publica produção sem a `main`).
- Migração com trava de host (G-16) e `--alvo` explícito; rollback não apaga o branch de restauração.
