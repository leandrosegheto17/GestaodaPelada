# RTP-0143 — deploy.yml: passo do Hyperdrive compatível com o wrangler 4.151.0

Reserva: Livre
ID no TASK.md: RTP-0143 · Lote: Refatoração Lote-30 · Agente: executor · Chapéu: Backend · Est: 0,25 d · Dep: TP-0135 · Status no TASK.md: Pendente
Reqs: G-15; G-17; QA da RTP-0139 e da RTP-0137 · Aceite: o passo que confere o cache do Hyperdrive usa uma chamada aceita pelo wrangler do lockfile (sem `Unknown argument: json`), com parse correspondente ao formato real da saída (ou API da Cloudflare); fixture/teste cobre o formato; a linha do id usa `pnpm --silent`; a falha continua fechada (G-17); `checar-wrangler-deploy` e `actionlint` em 0. **Bloqueante para o primeiro deploy.**

## 1. Plano de execução
Achado (QA da RTP-0139, confirmado pelo orquestrador): `wrangler hyperdrive get <id> --json` responde `Unknown argument: json` (rc 1) no wrangler 4.151.0; o comando só aceita o `<id>` e as flags globais. O passo 3 do `deploy.yml` falharia sempre, depois da migração já aplicada em produção. Achado da RTP-0137: a linha `id="$(pnpm exec tsx backend/scripts/ops/hyperdrive-id.ts)"` não usa `pnpm --silent`; aviso do pnpm no stdout contaminaria o `$id`.
Passos: (1) descobrir o formato real da saída sem credenciais: `wrangler hyperdrive get --help` não mostra; opções — saída em texto/tabela de `hyperdrive get` (parse por linha `caching`), ou chamada à API REST da Cloudflare (`GET /accounts/{account}/hyperdrive/configs/{id}`, que devolve JSON com `caching.disabled`) com o `CLOUDFLARE_API_TOKEN` já presente no job, via `curl` com o token por `env:` (sem eco). A API tem formato estável e documentado; preferir ela se o formato do `wrangler` não for estável ou não puder ser fixado em fixture. (2) fixture com o JSON documentado e teste do parse, com os casos: `caching.disabled` true (passa), false/ausente (falha), JSON inválido e erro HTTP (falha fechado). (3) manter a regra em um único lugar (script em `backend/scripts/ops/`, testado), não em `node -e` inline no YAML. (4) `pnpm --silent` na linha do id. Pendente do usuário depois: confirmar na execução real o formato (o QA não tem credencial).
**Reaproveitamento:** `backend/scripts/ops/hyperdrive-id.ts` e o parser `backend/scripts/comum/wrangler-jsonc.ts` (RTP-0137).

## 2. Plano de teste
- Vitest do script de verificação com fixtures (4 casos acima); `checar-wrangler-deploy` rc=0; `actionlint` (docker) rc=0.
- Conferir que `deploy.yml` não contém mais `--json` em `hyperdrive get` e que a forma escolhida é aceita pelo wrangler do lockfile (`--help`/dry-run sem rede).
