**Camada:** `backend/api/src/entrada/rotas/sessao/esqueci-senha.ts` → `entrada` (rota fina). A decisão "é admin? grava pedido" tem uma tabela só e cabe na rota chamando repositórios; se crescer além disso, mover para `aplicacao/acesso/`.
**Referência visual:** não se aplica (tela T05 é de outra tarefa).

1. TDD: testes de rota primeiro (Seção 2).
2. Rota sem sessão (pública de sessão). Validar o corpo pelo contrato (e-mail ≤ 254, formato, normalizado; strict) → 422 padrão com `campos.email` só para e-mail **malformado** (isso não revela existência).
3. Buscar a conta pelo e-mail normalizado; se for conta de admin (ver PENDENTE) → `registrar ou atualizar o pendente` (o repositório só atualiza a data se já houver, I-29); senão nada.
4. Responder sempre 200 com `{ mensagem: "Solicite o reset de senha a outro admin." }` — texto constante num único lugar (constante exportada do contrato se TP-0019 a criou; senão aqui), igual a `esqueci-senha.json`. `Cache-Control: no-store` (já global). Nenhum envio de e-mail, nenhuma integração.
5. Tempo semelhante (ADR-004 §6): os dois caminhos fazem a mesma busca; a gravação é um upsert único. Não acrescentar espera artificial nem hash.
6. Caso na suíte de isolamento: "não se aplica — rota de sessão sem dado de grupo" (G-04).

PENDENTE: o que é "e-mail de admin"? O `Usa` não inclui `repo/vinculos`, então o plano assume **conta existente que não é dono** (com ou sem vínculo). E o e-mail do **dono**: nada gravado (só o dono vê pedidos, RN-20; recuperação dele é pelo script, I-34) ou grava como qualquer conta? Plano assume "nada gravado". Confirmar os dois.

## 2. Plano de teste
`backend/api/test/rotas/sessao/esqueci-senha.test.ts` (pool de Workers + Postgres, cliente de teste com `X-Pelada`, fábricas que apagam o que criam, relógio fixo):
- admin existente → 200, corpo igual a `esqueci-senha.json` (validado por `EsqueciSenhaResposta`), 1 pedido pendente da conta.
- mesmo e-mail de novo com relógio avançado → continua 1 pendente, data atualizada.
- e-mail com maiúsculas/espaços → encontra a mesma conta.
- e-mail inexistente → 200 com corpo **byte a byte igual** ao do admin; nenhuma linha nova em pedidos.
- e-mail do dono → 200 igual; comportamento conforme resposta do PENDENTE.
- validação: e-mail vazio, sem `@`, 255 caracteres, campo extra, corpo não JSON → 422 com `campos`; corpo acima do limite → recusado.
- POST sem `X-Pelada` → 403 (CSRF global); `Cache-Control: no-store` presente.
- nenhum caminho chama envio (não há módulo de envio; conferir pelo diff).
- isolamento: rota listada na suíte com o caso "não se aplica" justificado; suíte verde.
