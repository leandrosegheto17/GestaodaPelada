1. `Campo`: `useId` gera `id`, `<id>-ajuda`, `<id>-erro`; entrega ao filho (render prop) `id`, `aria-describedby` (só os ids presentes, ajuda antes do erro), `aria-invalid` quando há erro; classe `campo--erro`; erro em `<p class="campo__erro">` com texto (nunca só borda). `role=alert` no erro só quando o campo é validado sozinho (mockup T11/T27); com `ResumoErros`, o alerta é do resumo.
2. `CampoSenha`: `type` password/text alternado por botão "Mostrar" com `aria-pressed` e `aria-controls`; rótulo do botão fixo (o estado é o `aria-pressed`); `autocomplete` obrigatório por prop (`current-password`/`new-password`); `maxLength` do contrato.
3. `CampoNumero`: botões −/+ com `aria-label` recebido ("Diminuir jogadores por time"), desabilitados nos limites `min`/`max`, `inputmode="numeric"`; slot à direita (caixa "Ilimitado" do T12 vem de TP-0097).
4. `CampoMoeda`: texto livre `inputmode="decimal"`, `placeholder="0,00"`; ao sair do campo chama `lerMoeda(texto, { min, max })`; `ok` → `aoMudar(centavos)`; falha → mensagem de `mensagensMoeda.ts` (formato: "Informe um valor em reais, ex.: 350,00."; faixa com mínimo 1: "O valor precisa ser maior que zero."). Textos de `casas` e `faixa` acima do máximo: ver decisão no fim do plano.
5. `CampoData`/`CampoHora`: nativos (`type=date`/`time`), valor `AAAA-MM-DD`/`HH:MM` sem conversão (ADR-012). `CampoSeletor`: `<select>` com opções recebidas (rótulos de `src/rotulos`, não aqui). `CampoNota`: `<select class="campo__entrada--nota">` com "–" (vazio) e 1..10 do limite do contrato.
6. `ResumoErros({ erros: { idCampo, rotulo }[] })`: só renderiza com 2+ erros; `Faixa tipo="erro"` (`role=alert`) com "Corrija n campos:" e lista de links `#id` que movem o foco para o campo.

## 2. Plano de teste
Vitest + Testing Library + `user-event` + `axe-core`, `src/componentes/campos/*.test.tsx` (TDD):
- Campo: `getByLabelText` acha a entrada; `aria-describedby` = "ajuda erro" na ordem, só ids existentes; `aria-invalid` só com erro; erro com texto.
- Senha: clicar "Mostrar" → `type=text` e `aria-pressed=true`, de novo volta; `aria-controls` aponta para a entrada; `maxLength` = limite do contrato.
- Número: − desabilitado no mínimo e + no máximo; clique altera o valor; digitação fora da faixa não passa do limite no `aoMudar`.
- Moeda (borda via `lerMoeda`): "350,00" → 35000; "1.234,5" → 123450; "0" → "maior que zero"; "abc" → formato; "1,234" → casas; estouro → faixa; vazio opcional.
- Nota: opções "–" + 1..10; "–" devolve `null`.
- ResumoErros: 1 erro → nada; 2 erros → `role=alert`, "Corrija 2 campos:", link move o foco.
- axe sem violação em cada variante, com e sem erro.
Comando: `pnpm --filter @pelada/web test -- componentes/campos`; `pnpm --filter @pelada/web lint:css`.

## 3. Plano de validação de segurança
- CONVENCOES §8: os limites vêm do contrato (mesma fonte da API); o campo limita no cliente, mas a validação de verdade continua na API (422 com `campos`), o campo só exibe.
- Senha: nada guardado fora do estado do formulário (sem `localStorage`, sem log); `autocomplete` correto; "Mostrar" não persiste.
- Nenhum `dangerouslySetInnerHTML` (mensagens da API renderizadas como texto); sem `style=` (G-22); só tokens (G-19).
