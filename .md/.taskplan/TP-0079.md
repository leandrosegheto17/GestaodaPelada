## 1. Plano de execução
**Reaproveitamento:** USAR `PartidaDetalhe` e o tipo `data` de `backend/contrato/src/partidas.ts`/`contrato/base` (TP-0024, TP-0005); `exigirVinculo` (TP-0032); `partidas.porData(db, grupoId, data)` → `{ choveu, alteradaPor, alteradaEm, presencas }` (TP-0049, última alteração já resolvida com `coalesce`); `ativosNaData` / `ordenarAtivosNaData` de `src/aplicacao/elenco/ativos.ts` (TP-0052); relógio e 404 de `src/entrada/erros.ts` (TP-0013); `casos.ts` (TP-0033). `montarLinhas(jogadores, presencas)` de `src/aplicacao/partidas/linhas.ts` — comum com TP-0078 (paralelo): ler antes; quem chegar primeiro cria (assinatura do TP-0078 §1).
**Camada:** `src/aplicacao/partidas/detalhe.ts` (`carregarPartida(db, grupoId, data, hoje)` → `PartidaDetalhe | null`) → `aplicacao`; `src/entrada/rotas/grupos/partidas/ler.ts` → `entrada`; uma linha em `src/entrada/app.ts` (reler antes).
**Referência visual:** não se aplica.

1. TDD (Seção 2) primeiro.
2. Rota `GET /api/grupos/:grupoId/partidas/:data{[0-9]{4}-[0-9]{2}-[0-9]{2}}` (padrão no parâmetro: `nova` do TP-0078 nunca cai aqui). Depois, `data` pelo schema do contrato: data impossível (`2026-02-30`) → 404 sem consulta (CONVENCOES §8, como id malformado).
3. `carregarPartida`: `porData` null → 404 `nao_encontrado`; senão ativos na data + `montarLinhas` com as presenças (sem presença → `ausente`), ordem alfabética do TP-0052. Resposta `{ data, hoje, choveu, alteradaPor, alteradaEm, jogadores }` validada por `PartidaDetalhe` (forma de `partida-2026-10-15.json`).
4. Data futura não precisa de regra: não há partida futura gravada → 404.
5. `casos.ts`: chave exatamente como o Hono lista a rota (com o padrão), `tipo: 'grupo'`, `parametros`: `data` de uma partida criada no cenário de A (para o 404 de B provar o isolamento, não a ausência).

DECIDIDO (Coordenador): incluir a linha (união ativos ∪ quem tem presença, ordem alfabética), para nenhuma presença ficar oculta; vale para a validação do TP-0080. Pergunta original: presença gravada de jogador que não está ativo na data (não deveria ocorrer pela L-11, mas pode vir de dado antigo/corrida). Proposta: incluir essa linha também (união ativos ∪ quem tem presença, em ordem alfabética) para nenhuma presença ficar oculta na edição; alternativa: só ativos. Confirmar — vale também para a validação comum do PUT (TP-0080).
