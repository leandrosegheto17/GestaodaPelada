1. TDD: testes de `publico`/`eventos` e o spec offline primeiro.
2. `useRankingComCache(slug, mes)`: lê o cache local em paralelo à rede; com cache e rede pendente → dados do cache + `atualizando`; rede OK → troca, grava o último ranking (chave = `mes` da resposta) e lembra o grupo; `ErroRede`/5xx com cache → dados do cache + `semConexaoDesde = geradoEm`; sem cache → erro da T01; 404 continua T03 (TP-0110). Sem `?mes=`, o cache usado é o do último mês corrente gravado para o slug (não calcular o mês no aparelho, G-06); se a API do TP-0107 não permitir isso, estender lá (mínimo, registrar).
3. `eventos.ts`: `registrarAbertura(slug)` envia `{ tipo: 'ranking_aberto', dispositivoId }` para `/publico/<slug>/eventos` uma vez por carregamento da página e slug (marca em memória do módulo, imune ao duplo efeito do StrictMode e à troca de mês), só depois de uma resposta da rede; erro engolido sem faixa nem log.
4. Ícones offline: com o último estado = sem conexão (ou `navigator.onLine === false`), o toque na engrenagem/"$" não navega e mostra a faixa de erro.

DECIDIDO (Coordenador): plugin no runtime caching do TP-0108 marca a resposta servida do cache (`X-Pelada-Cache: 1`); o gancho trata a marca como "sem conexão" (edição mínima na config do PWA, registrada em `## 4`). Pergunta original: com o service worker do TP-0108 (`/api/publico/*/ranking*` network-first, 3 s), sem rede a página recebe **200 do cache do SW**, não `ErroRede`, e não saberia mostrar "Sem conexão". Proposta: plugin no runtime caching de TP-0108 que marca a resposta servida do cache (ex.: cabeçalho `X-Pelada-Cache: 1`) e o gancho trata essa marca como "sem conexão" (edição mínima na config do PWA, registrada). ## 3. Plano de validação de segurança
- RF-57/LGPD: o evento leva só `tipo` e `dispositivoId` (uuid aleatório, sem relação com a pessoa); nada de user-agent, IP, nome; corpo validado pelo schema strict antes do envio.
- G-17/ADR-009: nada além do ranking público e do slug vai para o aparelho; conferir que nenhum dado de `/api/sessao` ou `/api/grupos` entra no armazenamento local ou no cache do SW.
- G-09: o POST passa por `escrever` (`X-Pelada: 1`); nenhum `fetch` solto. Cache local é entrada de fora: dado lido do IndexedDB volta a passar em `RankingPublico` antes de exibir.
