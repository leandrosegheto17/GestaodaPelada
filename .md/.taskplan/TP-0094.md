## 1. Plano de execução
**Reaproveitamento:** USAR `wrangler.jsonc` e `GET /api/saude` (TP-0013); `backend/scripts/migrar.ts` e a trava `infraestrutura/seguranca/trava-host.ts` (TP-0015, já aceita o host `db`); `backend/scripts/seed-local.ts` (TP-0051, idempotente); `frontend/web/vite.config.ts` e o script `dev` (TP-0088). Se o TP-0017 tiver criado um `docker-compose.yml` mínimo só com `db` (PENDENTE dele), completar esse arquivo em vez de criar outro. Nada a extrair.
**Camada:** `docker-compose.yml` na raiz (item de topo sem lógica, SDD §2); `frontend/web/vite.config.ts` (alterar: `server.proxy`); `backend/README.md`, `frontend/README.md`, `backend/.env.example`/`frontend/.env.example` (alterar).
**Referência visual:** não se aplica.

1. `db`: `postgres:16` (o contrib `pgcrypto` vem na imagem; a extensão é criada pela migração do TP-0025), `POSTGRES_PASSWORD`/`POSTGRES_DB=pelada` fictícios, porta `5432:5432` (a suíte da API e o TP-0017 usam o mesmo banco local), volume nomeado, `healthcheck` com `pg_isready`.
2. Imagem Node dos dois serviços de app: `node:22` + `corepack enable`, repositório montado em `/app`; `node_modules` em volumes nomeados (o do Windows tem binários nativos de outra plataforma: workerd, esbuild) e `pnpm install --frozen-lockfile` no início do contêiner (não altera o lockfile).
3. `backend`: `depends_on: db (service_healthy)`; comando = `migrar` → `seed-local` → `pnpm exec wrangler dev --ip 0.0.0.0 --port 8787` (raiz, onde está o `wrangler.jsonc`), com `DATABASE_URL=postgres://…@db:5432/pelada` para os dois scripts. "Migrações e seed na subida" ficam aqui porque o runner é TS (não cabe em `docker-entrypoint-initdb.d`) e o aceite fixa três serviços — registrar a interpretação em `## 4`. Hyperdrive local apontando para `db` pela variável de ambiente de sobrescrita do binding (`CLOUDFLARE_HYPERDRIVE_LOCAL_CONNECTION_STRING_HYPERDRIVE`, nome conforme a versão do wrangler instalada), sem mudar o `localConnectionString` do `wrangler.jsonc` (que continua servindo `wrangler dev` fora do Docker). `URL_PUBLICA` local por `--var URL_PUBLICA:http://localhost:5173`.
4. `frontend`: `depends_on: backend`; `pnpm --filter @pelada/web dev --host 0.0.0.0 --port 5173 --strictPort`; `ALVO_API_DEV=http://backend:8787`. Em `vite.config.ts`: `server.proxy['/api']` só quando `ALVO_API_DEV` existir (sem URL literal no código: G-18/`checar-urls-absolutas`), `changeOrigin: false` (mesma origem, como em produção); `server.watch.usePolling` quando `CHOKIDAR_USEPOLLING=true` (montagem do Windows não propaga eventos).
5. Se `checar-urls-absolutas` (TP-0002) varrer `.yml`, acrescentar `docker-compose.yml` à lista de exceções explícitas do topo do script e registrar.
6. READMEs: `docker compose up`, portas, contas do seed (já documentadas pelo TP-0051), `docker compose down -v` para zerar; `.env.example` com `ALVO_API_DEV` e `CHOKIDAR_USEPOLLING` sem valor real.

NÃO fazer: mudar `wrangler.jsonc`, scripts de migração/seed ou o lockfile; serviço de produção; segredo real.
