# TP-0032 — Middlewares de grupo (vínculo, financeiro) e de dono

Reserva: Livre
ID no TASK.md: TP-0032 · Lote: L07 · Agente: executor · Chapéu: Backend · Est: 0,75 d · Dep: TP-0031, TP-0029 · Status no TASK.md: Pendente
Reqs: ADR-005 §2, §4; RF-09, RF-18; G-03 · Aceite: `/api/grupos/:grupoId/*`: sessão completa + vínculo; sem vínculo ou arquivado → 404 padrão; `exigirFinanceiro` → 403 `sem_permissao` só para quem tem vínculo; `/api/dono/*`: e_dono, senão 404. Testes dos casos + uuid malformado → 404 sem consulta

## 1. Plano de execução
**Reaproveitamento:** USAR `exigirSessaoCompleta` e `c.var.sessao` de `src/entrada/middlewares/sessao.ts` e `entrarComo` de `test/apoio/sessao.ts` (TP-0031); `vinculos` (vínculo por conta e grupo) e `grupos` (por id, com `arquivado_em`) de `infraestrutura/db/repositorios/` (TP-0029) e suas fábricas; schema de uuid de `@pelada/contrato` (`limites.ts`/`contrato/base`, TP-0005); resposta 404 `nao_encontrado` de `src/entrada/erros.ts` (TP-0013). Nada a extrair.
**Camada:** `src/aplicacao/acesso/vinculo.ts` (caso de uso `carregarVinculo`), `src/entrada/middlewares/grupo.ts` (`exigirVinculo`, `exigirFinanceiro`), `src/entrada/middlewares/dono.ts` (`exigirDono`); montagem em `src/entrada/app.ts` (TP-0013).
**Referência visual:** não se aplica.

1. `carregarVinculo(db, grupoId, contaId)` → `{ grupoId, acessaFinanceiro }` só se o vínculo existe **e** o grupo não está arquivado; senão `null`. Preferir uma função de repositório que já filtre arquivado (uma consulta); se o TP-0029 só tiver as duas buscas separadas, usar as duas (sem SQL fora do repositório).
2. `exigirVinculo`: valida `:grupoId` pelo schema uuid **antes** de abrir banco → 404; depois `exigirSessaoCompleta` (401/PENDENTE do TP-0031 vêm antes do 404, pois não revelam grupo); `carregarVinculo` null → 404 padrão; senão `c.var.vinculo`. Dependência injetável (`criarExigirVinculo({ carregarVinculo })`) para o teste provar "sem consulta".
3. `exigirFinanceiro`: roda depois de `exigirVinculo`; `acessaFinanceiro` falso → 403. Sem vínculo nunca chega aqui (404 antes).
4. `exigirDono`: `exigirSessaoCompleta` + `c.var.sessao.conta.eDono` (já lido do banco nesta requisição, ADR-003) senão 404 padrão. Não dá acesso a `/api/grupos/*` (dono sem vínculo cai no 404 do vínculo, RF-07).
5. `app.ts`: registrar, **antes de qualquer rota de negócio**, `use('/api/grupos/:grupoId', …)` e `use('/api/grupos/:grupoId/*', exigirVinculo)`, `use('/api/grupos/:grupoId/financeiro/*', exigirFinanceiro)` (e a raiz `/financeiro`), `use('/api/dono/*', exigirDono)` (ADR-005: rotas registradas depois do middleware). Conferir no teste que o padrão do Hono pega `/api/grupos/:id` com e sem barra final.
6. Permissão relida a cada requisição (vínculo removido → 404 já na próxima, RF-15).

PENDENTE: código do 403 — o aceite diz `sem_permissao`, mas `.md/mockup/respostas/erro-sem-permissao.json` traz `sem_permissao_financeiro` ("Você não tem acesso ao financeiro deste grupo."). Proposta: seguir o arquivo de `respostas/` (é a forma que o [PR] e o contrato exigem). Confirmar.

Não fazer: rota de grupo/dono real (L11+); caso na suíte de isolamento (o TP-0033 nasce depois e cobre estes middlewares).

## 2. Plano de teste
`backend/api/test/rotas/mw-grupo.test.ts` e `mw-dono.test.ts` no pool de Workers, app = `criarApp` + rotas de eco do teste (`GET/POST /api/grupos/:grupoId/eco`, `/financeiro/eco`, `GET /api/dono/eco`); fábricas criam grupo A, grupo B arquivado/ativo, admin de A com financeiro, admin de A sem financeiro, admin de B, dono sem vínculo:
- admin de A em A → 200; admin de B em A → 404 `nao_encontrado` idêntico ao de grupo inexistente (uuid aleatório) — mesmo corpo e cabeçalhos; grupo arquivado com vínculo → 404; sem sessão → 401; escopo `troca_de_senha` → status do PENDENTE do TP-0031.
- financeiro: com permissão 200; vínculo sem permissão → 403 (forma de `erro-sem-permissao.json`); sem vínculo → 404 (nunca 403).
- dono: `eDono` em `/api/dono/eco` → 200; admin comum → 404; dono sem vínculo em `/api/grupos/A/eco` → 404.
- vínculo removido entre duas requisições com a mesma sessão → 2ª dá 404.
- uuid malformado (matriz §8): `abc`, uuid com 35/37 chars, `%2e%2e`, `' OR 1=1`, 10 KB de texto, vazio (`/api/grupos//eco`) → 404 e o `carregarVinculo` injetado não é chamado.
- POST sem vínculo também 404 (escrita), com `X-Pelada`.
Comando: `pnpm --filter @pelada/api test -- mw-grupo mw-dono`.

## 3. Plano de validação de segurança
- G-03/ADR-005: 404 sem diferença observável entre "não existe", "sem vínculo" e "arquivado" (corpo, status, cabeçalhos); 403 só para quem tem vínculo.
- Ordem dos `use` no `app.ts`: nenhum registro de rota antes deles (conferir no diff).
- RF-07/G-11: dono não ganha atalho para dados internos; `eDono` só lido, nunca escrito.
- Entrada: `grupoId` validado antes do banco; nenhum SQL fora dos repositórios (G-02).
