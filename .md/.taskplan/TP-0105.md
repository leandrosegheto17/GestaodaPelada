- `destinoAposEntrar`: dono sem destino → `/dono`; admin sem destino → `/admin`; destino `/admin/g-quinta` mantido.
- `lerDestino` (matriz adversarial, CONVENCOES §9): `//evil.com`, `/\evil.com`, `%2F%2Fevil.com`, `https://evil.com`, `javascript:alert(1)`, `/a%0d%0aSet-Cookie`, vazio, `null` → `null`; `/admin?x=1` → aceito.
- Roteamento (`RotaProtegida.test.tsx`): 401 → URL final `/entrar?destino=…`; troca de senha → `/entrar/nova-senha`; admin com vínculo renderiza o filho; erro de rede (`HttpResponse.error()`) renderiza o filho sem redirecionar; `useSair` chama POST com `X-Pelada: 1` e esvazia o cache.
- Comando: `pnpm --filter @pelada/web test -- src/dados src/app/guarda`.

## 3. Plano de validação de segurança
- Open redirect: todo `destino` passa por `lerDestino` (matriz acima); nunca `window.location = destino` sem validar.
- A guarda é conveniência de UX, não autorização: a API continua decidindo (G-03, 404 sem vínculo; `exigirSessaoCompleta` no escopo `troca_de_senha`, TP-0031). Conferir no diff que nenhuma tela passa a confiar só na guarda.
- G-09: sem `document.cookie`; `useSair` envia `X-Pelada: 1` (cliente do TP-0091) e limpa o cache de consultas (dados de admin fora da memória após sair).
- Nenhum log de `SessaoEu` (e-mail da conta).
